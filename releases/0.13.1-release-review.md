## Summary of changes

- **PDF preview sharpness fix**: `PdfViewer.tsx` previously rendered every page at a fixed `scale: 1.5` PDF.js viewport with no awareness of display density, so the canvas backing store was under-sampled relative to physical pixels on Retina/HiDPI displays — the standard cause of blurry `<canvas>` rendering. The fix computes an effective device pixel ratio (`window.devicePixelRatio`, falling back to `1` if unavailable/non-finite/non-positive), renders at `1.5 * effectiveDevicePixelRatio`, and pins the canvas's CSS `width`/`height` back down to the original logical size so on-page layout and existing zoom behavior are unchanged.
- **"About GitLocal" macOS menu item**: `AppDelegate.installMainMenu(for:)` now adds a standard `NSMenuItem` titled "About GitLocal" as the first item in the app menu, wired to AppKit's built-in `NSApplication.orderFrontStandardAboutPanel(_:)` (target `nil`, resolved via the responder chain) — no custom window or version-string plumbing, keeping the native wrapper thin per constitution Principle I. A matching manual-test-plan section was added to `ShortcutCommandTests.md`.
- **Version/changelog**: `package.json`/`package-lock.json` bumped to `0.13.1`; `CHANGELOG.md` updated with both fixes.

## Contrarian QA Review

An independent adversarial sub-agent review of the full diff (`git diff origin/main..HEAD`) examined correctness/regression risk, performance, security, accessibility, dead code, and test-coverage honesty for both functional changes.

Findings raised and their disposition — **all addressed** prior to release:

- **Canvas-dimension limits at high dpr** (minor, not new-in-kind): no explicit clamp against browser canvas-size limits (~16384px/dimension). Multiplying by device pixel ratio raises the odds of hitting this on an unusually large page, versus the pre-existing fixed `1.5` scale. **Fixed**: added `clampDevicePixelRatioToCanvasLimit` (`PdfViewer.tsx`), which caps the effective device pixel ratio so the rendered canvas backing store never exceeds a conservative `8192`px per dimension (chosen with the native macOS app's embedded WebKit engine in mind), while the on-page CSS size stays at the unclamped logical scale. Covered by a new test asserting a poster-sized page at `devicePixelRatio: 100` stays within the cap on both axes.
- **Divide-by-zero/NaN risk**: checked and ruled out — `getEffectiveDevicePixelRatio()` guards `dpr > 0 && Number.isFinite(dpr)` before any use. No issue. (The fix above also removed the one remaining division — CSS size is now read directly from the unscaled `baseViewport` rather than dividing the scaled viewport back down.)
- **dpr sampled per-page, not re-checked mid-page**: cosmetic-only (a page rendered while dragging the window across displays mid-render could very rarely mismatch), self-heals on next preview open. Accepted as-is — not worth the added complexity of a mid-render re-check for a cosmetic, self-healing edge case.
- **Cumulative memory across a long document**: progressive per-page rendering bounds *time-to-first-render*, but total memory for an N-page document still scales with N regardless of progressive loading (each rendered canvas is retained until unmount). This is an accurate characterization of pre-existing behavior, not a regression introduced by this change — the memory *per page* increases with dpr (now bounded by the canvas-dimension cap above), but the *shape* of the scaling (linear in page count) is unchanged from before this fix. No action needed.
- **Potential CSS conflict with the new inline canvas sizing** (initially flagged major, needs-verification): checked directly against `ui/src/styles/globals.css` and the full `ui/src` tree — **no CSS rule targets `.pdf-viewer-page` or `canvas` at all** (no `max-width`, no fixed width, nothing). There is nothing for the inline `canvas.style.width`/`height` to conflict with. **Resolved: not an issue.**
- **Swift/AppKit menu change**: `orderFrontStandardAboutPanel(_:)` with `target: nil` is Apple's documented standard pattern (resolves via the responder chain to `NSApplication`); no code in `AppDelegate.swift` or `ViewerWindowController.swift` indexes `appMenu.items` by position, so inserting "About GitLocal" + separator at the front doesn't disturb anything downstream. No issue found.
- **Security**: no new attack surface — pure rendering-math change plus a static, OS-provided About panel. No issue found.
- **Accessibility**: the PDF canvas's `aria-label` (`Page N`) is unchanged and independent of backing-store resolution; screen readers already treat it as an opaque labeled image. No regression found.
- **Test coverage gaps** (non-integer dpr, zero-page document): **addressed** — added a test for a fractional `devicePixelRatio` (`1.5`) confirming the linear scaling math holds, and a test confirming a zero-page document renders no page canvases and calls `render()` zero times with no crash.

No release-blocking correctness, security, performance, or accessibility issues found. All findings from the initial pass have been fixed or explicitly accepted with rationale above.
