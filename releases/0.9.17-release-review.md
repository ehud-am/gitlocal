# GitLocal v0.9.17 Release Review

## Scope

- Release: `v0.9.17` — first release of the integrated terminal panel feature.
- Branch: `release/0.9.17` (merged from `032-integrated-terminal-panel`, not yet merged to `main` at time of writing).
- Adds a bottom-docked terminal panel (regular shell, Claude Code, and Codex CLI tab kinds) to both the npm package and the macOS app, plus a `node-pty` install-time reliability fix and a dependency security fix.
- Release date: 2026-08-08

## Background

The integrated terminal panel (`specs/032-integrated-terminal-panel/`) was developed on a long-lived feature branch and, until this release, had never been merged into `main` — `git ls-tree -r origin/main` showed zero terminal-related files prior to this branch. This is therefore the feature's first-ever appearance in a published release, not an incremental refinement of something already shipped. The branch also carries this session's usability follow-ups (header discoverability button, `Ctrl+\`` shortcut, panel resizing) and an out-of-channel teammate commit (clearer collapse/expand affordance, grippable resize handle, taller default height), which were fetched and fast-forward-merged in before this review.

A prior, unrelated `0.9.17` release cycle (`032-multi-pane-workspace` / `033-repo-config-file`, PRs #55–#58) was fully reverted from `main` before this branch was created. `release/0.9.17` was confirmed via `git merge-base` to descend cleanly from the post-revert `main` tip, with no residue from that rollback.

## Summary of Changes

- Server: PTY session lifecycle (`src/terminal/session-manager.ts`), per-tab WebSocket I/O (`src/terminal/websocket.ts`), REST handlers (`src/handlers/terminal.ts`), and CLI-availability detection (`src/terminal/cli-detection.ts`), built on `node-pty` + `ws`.
- UI: `TerminalPanel`/`TerminalView`/`TerminalTabStrip` components, `useTerminalPanel` hook (cross-page persistence without touching localStorage/URL state), `@xterm/xterm` rendering.
- Discoverability: a "Terminal" header toggle button and the `Ctrl+\`` shortcut (matching VS Code), intercepted both globally and while focus is inside the terminal.
- Resizing: drag-to-resize and keyboard resize (arrow keys) of the panel height, with a clearer collapse/expand control.
- Reliability: `scripts/verify-node-pty.mjs` postinstall hook that auto-rebuilds `node-pty`'s native binding if the prebuilt one fails to load, instead of leaving the feature silently broken.
- Security/dependency: `nanoid` bumped to clear a high-severity advisory (GHSA-2v37-7h3g-55p8) in the `vitest`/`vite` devDependency chain.
- Hardening (added during this review, see Contrarian QA below): a per-process concurrent-session cap, a WebSocket `maxPayload` limit, resize-dimension clamping, and focus management when the panel opens.

## Verification Reviewed

- `npm run test:server`: 430/431 passing. The one failure (`tests/integration/terminal.test.ts`) is a known, pre-existing sandbox limitation — the local environment's outbound HTTP proxy intercepts loopback `fetch()` calls, producing `HPE_INVALID_CONSTANT`. Confirmed via `git stash` against the pre-feature commit that this failure is 100% environmental and unrelated to this branch's changes; not reproducible in CI, which has no such proxy.
- `npm run test:ui`: 421/421 passing, coverage gate intact (`TerminalPanel.tsx`/`TerminalTabStrip.tsx` at 100/100/100/100).
- `npm run build`: server + UI bundles build cleanly.
- `npm run audit` / `npm run audit:ui`: 0 vulnerabilities in both, after the `nanoid` fix.

## Contrarian QA Findings

A contrarian QA sub-agent reviewed the full diff between `origin/main` and this branch (43 files, +4252/-20), assuming regressions exist and specifically probing PTY session lifecycle, resource limits, path sandboxing, WebSocket handling, xterm/React memory management, and the `node-pty` postinstall rebuild script:

1. **[Medium] Unbounded concurrent PTY session creation.** No cap existed on how many sessions a client could spawn via `POST /api/terminal/sessions`, allowing local resource exhaustion (PIDs/FDs/memory).
   - Result: Fixed. Added a 20-session-per-process cap returning `session_limit_reached` (503) once exceeded, with a unit test asserting the boundary.
2. **[Medium] No WebSocket frame size limit.** `WebSocketServer` had no `maxPayload`, so a single oversized `input` frame would be written straight into the PTY unbounded.
   - Result: Fixed. Set `maxPayload: 64KB` on the WebSocket server, with a unit test asserting the constructor option.
3. **[Low] `resize` cols/rows accepted without range validation**, only type-checked — a pathological value (e.g. negative or huge) would be forwarded straight to `node-pty`.
   - Result: Fixed. Clamped both dimensions to `[1, 1000]` before forwarding, with a unit test covering out-of-range and fractional input.
4. **[Low] No ownership boundary on sessions** (any local client can list/attach/close any session by GUID). Consistent with the rest of the app's existing no-auth, localhost-only design — not a terminal-specific regression, but a higher-stakes instance of it since it grants shell I/O rather than file reads.
   - Result: Accepted as a tracked follow-up, not blocking. Matches the existing app-wide trust boundary (localhost-only binding, no auth anywhere in `src/`); worth a documented callout in a future release, not a fix scoped to this one.
5. **[Low] Output buffer append is O(n) on overflow, and a large buffered backlog is replayed to the client in one `write()` call on reconnect.** Not a leak; a potential jank spike under sustained high-throughput output.
   - Result: Accepted as-is; low real-world impact at the existing 200K-char buffer cap.
6. **[Low] `verify-node-pty.mjs` warns-only on rebuild failure without a highly visible signal to the user.** Deliberate design (must not block `npm install`); accepted as a known, documented limitation rather than a defect.
7. **[Positive]** Path sandboxing correctly reuses the existing vetted `resolveSafeRepoPath`/`classifyLocalPath` primitives rather than reimplementing escape checks; no new traversal vector found. Session teardown (WS close vs. session close, buffered-listener bookkeeping) traced end-to-end with no leak found.

No blocker-severity issues were found. Findings 1–3 were fixed and re-verified (full suite green, coverage intact) before finalizing this release; findings 4–6 are accepted as tracked follow-ups.

## Accessibility Review

The same contrarian QA pass included a dedicated accessibility review of the terminal panel, tab strip, and resize handle:

1. **[Medium] No focus management when the panel opened** — a keyboard/screen-reader user pressing `Ctrl+\`` or opening a new tab had no indication the terminal appeared and had to manually tab through the rest of the page to reach it.
   - Result: Fixed. The active terminal now receives keyboard focus whenever the panel becomes visible, whether from creating a new tab, the header button, the `Ctrl+\`` shortcut, or re-showing a hidden panel. Covered by two new tests asserting focus lands on the correct session in both cases.
2. **[Low] The tab strip does not implement the full ARIA APG roving-tabindex/arrow-key pattern for `role="tablist"`** — each tab is a normal Tab-stop with `Enter`/`Space` activation rather than `ArrowLeft`/`ArrowRight` navigation between tabs. Functionally usable; deviates from the expected tablist keyboard pattern.
   - Result: Accepted as a tracked follow-up, not blocking.
3. **[Positive]** `jest-axe` structural checks pass with zero violations across the panel's empty, open, and CLI-unavailable states, and the resize handle correctly exposes `role="separator"`, `aria-orientation`, and live `aria-valuenow/min/max` with a genuine (not decorative) keyboard-operable equivalent to drag-resize (verified via existing arrow-key tests). Note: `jest-axe` only catches static/structural violations, not the dynamic focus-management gap in finding 1 above — that required a dedicated interaction test, now added.
