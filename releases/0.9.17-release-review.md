# GitLocal v0.9.17 Release Review

## Scope

- Release: `v0.9.17` — post-032/033 stabilization: a startup-crash fix, a packaging gap, a graceful-degradation fix, and workspace UI styling/a11y follow-up.
- Branch: `fix/esm-bundle-native-deps` (not yet merged to `main` at time of writing).
- Prompted by: `032-multi-pane-workspace` and `033-repo-config-file` merging to `main`, followed by a routine "run a full prerelease cycle" request. All findings below were discovered during that cycle, not reported externally.
- Release date: 2026-08-06

## Background

`032-multi-pane-workspace` added terminal panes (via `node-pty`) and their WebSocket transport (via `ws`) to the server bundle. Neither had been exercised through a real `npm run build` + `node dist/cli.js` run before merge — `npm test` alone does not catch bundling failures, since tests run against source, not the built artifact. A prerelease cycle's build-and-run validation caught what unit tests structurally could not.

## Root Cause

`package.json` has `"type": "module"`, and `build:server` bundles `src/cli.ts` to a single ESM file via esbuild with `--platform=node --format=esm`. esbuild's ESM output wraps any bundled CommonJS dependency's internal `require()` calls (Node builtins like `"events"`, or native `.node` addon loaders) in a generic `__require` shim with no real `require` available at ESM runtime — throwing `Dynamic require of "..." is not supported`. This affected both `ws` (its own internal `require("events")` etc.) and `node-pty` (its dynamic native-binding loader in `node-pty/lib/utils.js`). `dist/cli.js` crashed on startup on every platform, before the server ever bound a port — confirmed by direct reproduction (`node dist/cli.js <repo>`).

A second, independent issue was found via a Contrarian QA pass on the fix: `node-pty` was statically imported at the top of `terminal-server.ts`, itself statically imported by `cli.ts`. ESM's eager module-graph evaluation ran node-pty's native-binding load *before* `main()` — meaning even after externalizing the dependency correctly, a genuine runtime load failure (missing prebuild for the platform/arch, no build toolchain to compile one) would still crash the entire app over a feature the rest of GitLocal doesn't depend on. This is architecturally the same severity/blast-radius as the original bug, just triggered by a different condition (runtime load failure vs. bundling), so it was fixed within this cycle rather than deferred.

A third issue, unrelated to bundling, was found by the accessibility review: `032`'s task list included three CSS tasks (T022, T032, T048) and an accessibility-review task (T051), all left unchecked at merge time. Confirmed via `grep` that `ui/src/styles/globals.css` had zero rules for any `workspace-*`/`terminal-pane-*` class — the entire multi-pane workspace UI (tabs, tiled layouts, terminal panes, layout switcher) rendered unstyled in production.

## Fix

- `package.json`: `build:server` now passes `--external:ws --external:node-pty` to both esbuild invocations, so esbuild emits real ESM `import` statements and lets Node's own module resolution (which correctly handles builtins/CJS interop/native addons) handle them at runtime.
- `packaging/macos/release/package-app.sh`: now copies `node_modules/ws` and `node_modules/node-pty` into the packaged app's `Contents/Resources/gitlocal/node_modules/` — previously the script shipped no `node_modules` at all, which would have broken the app even after the externalization fix. `test-package.sh` gained corresponding assertions.
- `ui/vite.config.ts`: added an `xterm` manual chunk (mirroring the existing `markdown` chunk split) after `@xterm/xterm`/`@xterm/addon-fit` pushed the main UI bundle from ~500kB back over the chunk-size warning threshold a prior release had fixed. Main chunk dropped from 759.22kB to 416.97kB (now 417.27kB after this release's additional CSS).
- `src/services/terminal-server.ts`: `attachTerminalServer` is now async and dynamically `import()`s `node-pty` inside a try/catch; on failure it logs a clear warning and supplies a `spawnPty` that throws a controlled error instead of crashing at import time.
- `src/handlers/terminal.ts`: `openSession()` wraps the `spawnPty()` call in try/catch, sending a `{type:'error', message}` payload to the client and closing the socket (1011/`terminal-unavailable`) instead of throwing uncaught inside the WS upgrade callback.
- `src/cli.ts`: updated to `await attachTerminalServer(...)`.
- Client side needed no changes: `terminalSocket.ts`'s close handler already treats any non-1000 close code as a failure, and `TerminalPane.tsx` already renders a `role="alert"` "Connection lost." banner for it.
- `ui/src/styles/globals.css`: added a single CSS block covering every `workspace-*`/`terminal-pane-*` class, reusing existing design tokens and patterns (`root-view-tab`'s active-tab treatment, `file-tree-node`'s selected-state `color-mix`, `btn-raw`'s button reset, `manual-editor-conflict`'s tinted-banner style) rather than introducing new visual language. Grid layouts (2-column/4-tile/6-tile) implemented as CSS Grid per `WORKSPACE_LAYOUT_TILE_CAPACITY`.
- `ui/src/components/Workspace/TabStrip.tsx`: fixed focus silently dropping to `<body>` when the active tab was closed — focus now moves to the newly-active tab's button.

## Contrarian QA Findings

A contrarian QA sub-agent reviewed the bundling fix, `032`, and `033` together, assuming a regression exists and attempting to disprove release-readiness:

- **Flagged and fixed**: `node-pty`'s static top-level import meant a runtime native-binding load failure would crash the entire app, not just degrade the terminal-pane feature. See Root Cause / Fix above.
- **Noted, not fixed — accepted pre-existing risk**: `node-pty` requiring a native binding for the platform/arch is a known packaging risk already flagged in `specs/032-multi-pane-workspace/tasks.md` (T052, explicitly called "same class as the v0.9.16 `libnode.dylib` bug") and `plan.md`. This release's fix changes the *failure mode* from "whole app crashes" to "terminal panes gracefully degrade" — it does not and cannot eliminate the underlying possibility of a missing prebuild on an unusual platform/arch, which remains an accepted product risk.
- **Noted, not fixed — intentional/documented scope**: `033-repo-config-file`'s persisted layout (`{branch, path, pathType, raw}`, per `spec.md` FR-014) does not cover pane/terminal state — closing and reopening a repo drops any open multi-pane layout back to a single pane. This is documented scope, not a regression, but worth surfacing here since it interacts with 032's UX.
- **Noted, not independently verified this cycle**: whether the WS terminal upgrade route has any auth/origin hardening beyond same-origin browser defaults. Not exercised as part of this release's changes; flagged as a possible follow-up, not a blocker.

## Accessibility Review

A dedicated accessibility review of `032`'s workspace UI (033 has no independent UI surface — it's a silent data-persistence contract) found:

**Blockers (fixed this release):**
- No CSS existed for any workspace/terminal-pane class — see Root Cause/Fix above.
- Closing the active tab dropped keyboard focus to `<body>` with no way to recover it via keyboard — see Fix above.

**Confirmed well-implemented (no action needed):**
- `TerminalPane.tsx`'s connection-status handling: a persistent `role="status" aria-live="polite"` div always announces connection state in text (not color-only), plus distinct `role="alert"` banners for "ended" vs. "error" states.
- `TabStrip.tsx`'s `tablist`/`tab` roles, `aria-selected`, `aria-controls` wiring, roving `tabIndex`, working Left/Right arrow-key navigation, keyboard close via Delete/Backspace, and accessible close-button labels.
- `PaneTile.tsx`'s `tabpanel`/`aria-labelledby` pairing with its owning tab.
- `LayoutSwitcher.tsx`'s `aria-label` reflecting current selection and real `disabled` attributes (not just visual styling) for unavailable layouts.

**Should-fix, deferred (not blockers, not part of this release):**
- `TabStrip.tsx` has no Home/End key support to jump to the first/last tab, useful given the explicit "stays usable with 20+ tabs" requirement.
- `LayoutSwitcher.tsx`'s `role="radiogroup"` options don't implement roving-tabindex/arrow-key navigation, which is the expected ARIA authoring pattern for radiogroups (currently every option is a separate Tab stop).
- `TerminalPane.tsx`'s "ended" and "error" banners are two independently-mounted elements; if a state transition happened directly between them without an unmount in between, some screen readers might not re-announce. Low risk given these are effectively terminal states in the session lifecycle.

**Nice-to-have, deferred:**
- `PaneTile.tsx`'s empty-tile placeholder uses an identical `aria-label="Empty tile"` for every empty tile in a grid layout, making them indistinguishable by role to screen reader users. Consider indexing (`"Empty tile 3"`).
