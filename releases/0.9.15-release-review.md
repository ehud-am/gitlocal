# GitLocal v0.9.15 Release Review

## Scope

- Release: `v0.9.15`
- Feature: 031-json-viewer — pretty/structured collapsible tree rendering for `.json` files in the content panel, matching the existing Markdown pretty/raw/edit pattern; raw/pretty toggle for valid JSON; malformed/empty JSON always falls back to raw view with an inline notice; non-blocking save-time warning when saved content is not valid JSON.
- Branch: `031-json-viewer` (not yet merged to `main`; this review covers the branch's working tree as the pre-release cycle basis)
- Release date: 2026-08-03

## Verification Reviewed

- `npm run verify` passed on branch `031-json-viewer`: test + build + both audits.
- UI test suite: 30 files, 376 tests, all passing (includes 9 new/updated tests added directly for this feature, plus one accessibility check and one large-array regression test added during this pre-release review).
- Server test suite: 13 files, 369 tests, all passing.
- Coverage (all touched files ≥90% branch per Constitution Principle II): App.tsx 90.02%, ContentPanel.tsx 92.05%, src/git/repo.ts 90.21% branch. `json-tree.ts`/`JSONViewer.tsx` are intentionally outside the UI coverage gate's `include` allowlist, matching the existing precedent for the Markdown front-matter parser/renderer (`markdown-frontmatter.ts`/`MarkdownRenderer.tsx`); both still carry dedicated, thorough unit suites (json-tree.test.ts, JSONViewer.test.tsx).
- `npm run build` passed cleanly: `JSONViewer` correctly code-split into its own lazy-loaded chunk (`dist/assets/JSONViewer-*.js`, 1.52 kB), no chunk-size or deprecated-dependency warnings.
- Root npm audit: 0 vulnerabilities. UI npm audit: 0 vulnerabilities.

## Contrarian QA Findings

A contrarian QA sub-agent reviewed the full diff on `031-json-viewer` against `specs/031-json-viewer/spec.md` and `specs/031-json-viewer/contracts/json-viewer-ui.md`, assuming regressions exist and attempting to disprove release readiness:

- `src/git/repo.ts`'s JSON type detection is special-cased ahead of the generic `langMap` lookup with no comment explaining why, risking a future silent no-op if someone re-adds `json` to `langMap`.
  - Result: Fixed. Added a one-line comment at `src/git/repo.ts:1805`.
- The feature's own UI contract (`contracts/json-viewer-ui.md`) calls for regression coverage of "a deeply nested structure and a large array, exercising collapse/expand," but only deep nesting had a test; wide/large arrays were untested against the tree's non-virtualized, one-`useState`-per-node rendering.
  - Result: Fixed. Added a 2,000-item array test to `JSONViewer.test.tsx` asserting it renders and collapse/expand still functions.
- Malformed-JSON + `canMutateFiles=true` combined case (edit still offered, raw/pretty toggle correctly hidden) was verified correct by code tracing but not previously asserted by a test.
  - Result: Accepted for this release, not blocking. Noted as a nice-to-have follow-up; the underlying logic (`canToggleRaw` false when type is `json` and invalid) was independently traced and confirmed correct.
- Prototype-pollution-shaped keys (`__proto__`, `constructor`), duplicate keys, number precision loss, `NaN`/`Infinity`: all confirmed to inherit safe, standard `JSON.parse`/React-escaping behavior; no XSS vector (no `dangerouslySetInnerHTML` anywhere in the new code), no pollution risk, no new class of bug introduced.
- No virtualization on the JSON tree for very large documents: confirmed consistent with the existing `CodeViewer`'s equally non-virtualized rendering for large files — not a new regression, matches the plan's stated scope.
- Raw/pretty toggle state machine, malformed/empty fallback, and save-time warning were traced end-to-end against every acceptance scenario in `spec.md` and every bullet in the UI contract; no mismatch found.

No remaining release blocker was found after the two fixes above.

## Accessibility Review

- Added a `jest-axe` check on the default JSON tree view (`ContentPanel.test.tsx`, "shows the JSON tree view by default for valid JSON files"): 0 violations.
- Collapse/expand toggles are real, keyboard-operable `<button>` elements with `aria-expanded` state (`JSONViewer.tsx`), an improvement in operability over a static/always-expanded tree.
- New `.json-tree-key` styling reuses the existing `--muted-foreground` custom property (same rule shape as the precedent `.markdown-metadata-key`), which already passes WCAG AA contrast in both light (~6.1:1) and dark (~6.15:1) themes.
