# GitLocal v0.10.2 Release Review

## Scope

- Release: `v0.10.2` — six patch-level bug fixes/relocations from `specs/034-patch-bugfixes/` (US1-US6), plus follow-up Picker-page polish (scroll fix, floating sidebar collapse toggle, Parent Folder button) found during live verification of this branch.
- Branch: `034-patch-bugfixes`, 11 commits ahead of `origin/main`. 25 files changed, 1334 insertions(+), 165 deletions(-).
- Release date: 2026-08-15

## Summary of changes

- **US1**: Fixed the folder/content view losing the ability to scroll to its last entry depending on terminal panel visibility/state/height (`min-h-0` fix on `content-area`).
- **US2**: Fixed Claude/Codex terminal tabs failing with a "not found on PATH" error when the CLI is only resolvable via shell profile scripts, by resolving via the same mechanism an interactive login shell uses; a genuinely missing CLI still fails closed with the existing error (`src/terminal/cli-detection.ts`).
- **US3**: Added a Ctrl+`` ` `` terminal-toggle shortcut and a matching native macOS "Toggle Terminal" menu item.
- **US4**: Unified dotfile visibility into a single global setting driving both the sidebar file tree and content panel, replacing two independent/unsynchronized toggles; exposed via native app menu (macOS) or a single toolbar "View options" dropdown (browser).
- **US5**: Moved Refresh into "View options"/native menu behind Ctrl+Alt+R, removing the standalone toolbar button while keeping it reachable via shortcut and a non-keyboard-only control.
- **US6**: Moved the Tracked/All/Local files-visibility selector into the same "View options" dropdown/native menu.
- **Additional Picker-page fixes** (found during live verification, not in the original spec): restored independent scrolling in the picker's sidebar and main panes, floated its sidebar collapse toggle to match the main app's pattern, and added a "Parent Folder" button to its header.

## Contrarian QA Findings

A dedicated contrarian-QA sub-agent reviewed the full `034-patch-bugfixes` vs `main` diff, assuming regressions exist rather than presuming release-readiness. Findings:

1. **[Medium, no fix needed]** Two distinct "Parent Folder" mechanisms now exist with identical labeling: the main app's button (`App.tsx`) triggers a server-side `pickerPath` mutation, viewer-state reset, and full page reload when leaving a repository; the new Picker-page button (`PickerPage.tsx`) just re-browses locally via `loadPath`, with no reload or server mutation. Each is correct in its own context, but a user who's seen one may have mismatched expectations of the other (e.g. expecting state to survive a reload either way). Not a functional bug; worth a follow-up to visually/textually differentiate the two if it causes confusion in practice.
2. **[Low, no fix needed]** `src/terminal/cli-detection.ts`'s login-shell probe interpolates `command` into a shell string (`command -v ${command}`). Not exploitable today — the only call sites pass the literals `'claude'`/`'codex'` — but flagged as a latent injection risk if this helper is ever generalized to accept externally-controlled CLI names. Recommend a defensive comment or switching to positional-arg passing in a follow-up; not a release blocker.
3. **[Medium, no fix needed]** The login-shell PATH-resolution fallback (US2) runs synchronously and unmemoized, adding up to ~4s of event-loop-blocking latency in the worst case (both `claude` and `codex` misses) on every capabilities check. This only triggers when the direct PATH lookup already missed (not the common case), so it's an acceptable tradeoff for a patch release, but worth memoizing per-process in a follow-up.
4. **[Low, no fix needed]** Some CSS selectors (`.file-tree-controls`, most of `.dotfile-toggle`) are now orphaned after their JSX consumers were removed as part of the US4-US6 relocations. Purely dead weight, no runtime effect; cleanup deferred to a follow-up rather than blocking this release.
5. **[Medium, no fix needed]** The new macOS menu-item checkmarks (`dotfilesMenuItem`, `trackedVisibility*Item`) default to `NSMenuItem`'s off-state until the WebView's first JS tick posts the real state back via `postNativeAppCommand`. Self-heals almost immediately after mount (React effects run after first render) — a cosmetic flash at worst, not a functional bug.
6. **[Positive]** No accessibility violations found: Radix's `DropdownMenuCheckboxItem`/`RadioItem` primitives supply `role="menuitemcheckbox"`/`role="menuitemradio"` and `aria-checked` automatically; new controls (View options trigger, Picker's Parent Folder and theme toggle) all carry `aria-label`s; keyboard operability is inherited from Radix, not reimplemented.
7. **[Positive]** New/changed tests assert observable behavior (DOM state, round-trips through `viewerState`, fail-closed PATH-resolution timeouts) rather than implementation details. One noted coverage gap: the `min-h-0` scroll-fix regression test only asserts the CSS class is present, not that scrolling actually reaches the last entry — acceptable given jsdom's lack of real layout, but weaker than a true behavioral assertion; the live `agent-browser` verification in this review closes that gap for this release.
8. **No blockers identified.** All six user stories' acceptance criteria are met as specified; no dangling JSX-level controls from the relocations (only stale CSS, item 4).

## Accessibility Review

- Existing `jest-axe` coverage on every touched component confirms 0 violations post-change: `App.test.tsx` (including a dedicated collapsed-navigation-rail test that also verifies keyboard tab order reaches the "expand navigation" control), `ContentPanel.test.tsx`, `FileTree.test.tsx`, and `PickerPage.test.tsx` (default render, which includes the new floating toggle and Parent Folder button).
