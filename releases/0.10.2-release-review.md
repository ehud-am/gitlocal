# GitLocal v0.10.2 Release Review

## Scope

- Release: `v0.10.2` — six patch-level bug fixes/relocations from `specs/034-patch-bugfixes/` (US1-US6), plus follow-up Picker-page polish (scroll fix, floating sidebar collapse toggle, Parent Folder button) found during live verification of this branch.
- Branch: `034-patch-bugfixes`, 11 commits ahead of `origin/main`. 25 files changed, 1334 insertions(+), 165 deletions(-).
- Release date: 2026-08-15

## Summary of changes

- **US1**: Fixed the folder/content view losing the ability to scroll to its last entry depending on terminal panel visibility/state/height (`min-h-0` fix on `content-area`).
- **US2**: Fixed Claude/Codex terminal tabs failing with a "not found on PATH" error when the CLI is only resolvable via shell profile scripts, by resolving via the same mechanism an interactive login shell uses; a genuinely missing CLI still fails closed with the existing error (`src/terminal/cli-detection.ts`).
- **US3**: Added a Ctrl+`` ` `` terminal-toggle shortcut and a matching native macOS "Toggle Terminal" menu item.
- **US4**: Unified dotfile visibility into a single global setting driving both the sidebar file tree and content panel, replacing two independent/unsynchronized toggles; exposed via native app menu (macOS) or a single toolbar "View options" dropdown (browser).
- **US5**: Moved Refresh into "View options"/native menu behind Ctrl+Alt+R, removing the standalone toolbar button while keeping it reachable via shortcut and a non-keyboard-only control.
- **US6**: Moved the Tracked/All/Local files-visibility selector into the same "View options" dropdown/native menu.
- **Additional Picker-page fixes** (found during live verification, not in the original spec): restored independent scrolling in the picker's sidebar and main panes, floated its sidebar collapse toggle to match the main app's pattern, and added a "Parent Folder" button to its header.

## Contrarian QA Findings

A dedicated contrarian-QA sub-agent reviewed the full `034-patch-bugfixes` vs `main` diff, assuming regressions exist rather than presuming release-readiness. All actionable findings below were fixed before merge, per an explicit quality-bar request; none were left as "acceptable to ship as-is."

1. **[Medium, fixed]** Two distinct "Parent Folder" mechanisms exist with identical labeling: the main app's button (`App.tsx`) can either navigate locally within the repository (the common case) or, from the exact repository root, leave the repository via a server-side `pickerPath` mutation + reload — already gated behind the existing `RepoBoundaryDialog` confirmation ("Leave this repository?"); the Picker-page button (`PickerPage.tsx`) always navigates locally via `loadPath`, which was already accurate. Fixed by adding a dynamic `title` tooltip on the main app's button that previews which behavior a click will trigger ("Leave this repository and browse its parent folder" vs. "Go to parent folder"), without changing its constant `aria-label="Parent Folder"` (so no existing accessible-name-based test needed updating).
2. **[Low, fixed]** `src/terminal/cli-detection.ts`'s login-shell probe interpolated `command` into a shell string (`command -v ${command}`). Not exploitable today (only literal call sites), but hardened as defense-in-depth: added a `SAFE_COMMAND_NAME` allow-list regex checked before interpolation, and switched to positional-arg-safe quoting (`command -v -- '${command}'`). New test asserts unsafe command names are rejected without ever reaching `execFileSync`.
3. **[Medium, fixed]** The login-shell PATH-resolution fallback (US2) ran synchronously and unmemoized, up to ~4s of blocking latency per capabilities check on a miss. Fixed via a 30s TTL in-process memoization cache (`loginShellProbeCache`), with a `resetLoginShellProbeCache()` export used for test isolation. New test confirms a cached hit doesn't re-invoke `execFileSync`.
4. **[Low, fixed]** `.file-tree-controls` and most of `.dotfile-toggle`/`.dotfile-toggle input` were orphaned after their JSX consumers were removed in the US4-US6 relocations. Removed both dead rules from `globals.css` (kept `.dotfile-toggle-count`, still used by `ContentPanel.tsx`). Updated `globals.test.ts`'s corresponding assertions to match the current live selectors.
5. **[Medium, fixed]** The macOS menu-item checkmarks (`dotfilesMenuItem`, `trackedVisibility*Item`) defaulted to `NSMenuItem`'s off-state until the WebView's first JS tick posted the real state back. Fixed by setting each item's initial `.state` at menu-build time in `AppDelegate.swift` to match the UI's documented defaults (`DEFAULTS.hideDotfiles = false`, `DEFAULTS.generatedLocalVisibility = 'hide'`), so the checkmarks are already correct before the first round-trip in the common case.
6. **[Positive]** No accessibility violations found: Radix's `DropdownMenuCheckboxItem`/`RadioItem` primitives supply `role="menuitemcheckbox"`/`role="menuitemradio"` and `aria-checked` automatically; new controls (View options trigger, Picker's Parent Folder and theme toggle) all carry `aria-label`s; keyboard operability is inherited from Radix, not reimplemented.
7. **[Positive]** New/changed tests assert observable behavior (DOM state, round-trips through `viewerState`, fail-closed PATH-resolution timeouts) rather than implementation details. One noted coverage gap: the `min-h-0` scroll-fix regression test only asserts the CSS class is present, not that scrolling actually reaches the last entry — acceptable given jsdom's lack of real layout, but weaker than a true behavioral assertion; the live `agent-browser` verification in this review closes that gap for this release.
8. **No blockers identified.** All six user stories' acceptance criteria are met as specified.
