## Summary of changes

- **Simplified startup folder resolution**: The prior 5-tier fallback chain (`explicit` → `last-used` → `platform-default` [Documents] → `home-fallback` → `safe-fallback` [cwd/tmp/filesystem root]) — spread across three semi-independent resolvers (`resolveStartupFolder`, `initializePaths`, and `resolveOpenTarget`) that could each compute a fallback slightly differently — is now 3 tiers (`explicit` → `last-used` → `os-default`), with exactly one function (`resolveOsDefaultLocation`) deciding the OS-default location (home directory, falling through once to the filesystem root only if home itself is unreadable). Every startup failure mode (a bad explicit path, a missing/unreadable remembered folder, a blocked native file-open, a repo that vanished mid-session, a parent-folder walk with no readable ancestor) now converges on this one function and one outcome shape, addressing the user-reported "startup failed in ways I can't reliably reproduce" problem by eliminating the divergent fallback paths that could cause it.
- **One repo-vs-independent-folder classifier**: `resolveDirectOpenTarget` (`src/git/repo.ts`) is now the single implementation of "given a directly-opened file, is it inside a repo or not, and what's the resulting tree root/selection" — used identically by the native "open with" startup path and the runtime "open this file" API, which previously computed this rule independently in two places.
- **Hardened "last viewed" persistence**: `writeStartupFolderPreference` now structurally rejects a path that's inside a git repository but isn't that repository's root (previously this was only true by convention at every real call site, not enforced). The one HTTP surface that could have violated it — `PUT /api/startup-folder`, which had zero UI callers — is removed.
- **Fixed a real, user-facing display bug found during manual verification**: opening any plain (non-repository) folder — including the new home-directory OS-default fallback itself — could show "0 visible items" even with real content present, because the "hide generated/local files" filter (default: hide) was being applied to folders where the tracked-vs-generated distinction doesn't exist. Now skipped entirely outside a git repository.
- **Version/changelog**: `package.json`/`package-lock.json` bumped to `0.13.2`; `CHANGELOG.md` updated with all four user-facing fixes.

## Contrarian QA Review

An independent adversarial sub-agent review of the full diff (`git diff origin/main..HEAD`) re-derived old-vs-new behavior line-by-line (not trusting commit messages), independently re-ran the full server and UI test suites with coverage, and grepped the whole tree — including `native/macos/`'s Swift sources, which can't be type-checked by `tsc` — for stale references to every removed symbol and API shape.

Findings and disposition — **no issues found, no fixes required**:

- **3-tier resolver vs. old 5-tier resolver**: verified the new explicit-path-invalid branch always falls through to `resolveOsDefaultLocation()` instead of ever returning an unresolved/nonexistent path (a behavior the old code *could* exhibit) — an improvement, not a regression.
- **`env`/`XDG_DOCUMENTS_DIR` removal**: confirmed zero remaining references anywhere in the codebase; tests were rewritten to match, not left dangling.
- **`resolveDirectOpenTarget` equivalence**: confirmed byte-for-byte equivalent to both removed inline implementations (dirname/relative/basename semantics, backslash normalization), backed by new direct unit tests.
- **`generatedLocalVisibility` fix threading**: `isGitRepo` was already a correctly-threaded prop with correct `useMemo`/`useCallback` dependencies in both `FileTree.tsx` and `ContentPanel.tsx` prior to this change — no stale-closure risk introduced; repo behavior (`isGitRepo === true`) is byte-identical to before.
- **Security**: no dangling client reference to the removed `PUT /api/startup-folder` endpoint (UI or native Swift); the new `writeStartupFolderPreference` guard operates on the already-canonicalized (`realpathSync`'d) path, so no symlink bypass; no new path-traversal surface in `resolveDirectOpenTarget`.
- **Performance**: `resolveOsDefaultLocation` makes at most 2 filesystem checks versus the old 5-candidate chain's worst case of 5 — a net reduction, not a regression; no new synchronous filesystem calls added to `/api/info`'s steady-state path.
- **Accessibility**: independently re-ran `PickerPage.test.tsx`, `FileTree.test.tsx`, and `ContentPanel.test.tsx` (151 tests) — all `axe(container)` zero-violation assertions still pass.
- **Dead code**: grepped all of `src/`, `ui/src/`, `tests/`, `native/` for every removed symbol/type/string (`platform-default`, `home-fallback`, `safe-fallback`, `resolveGuaranteedFallbackPath`, `getPlatformDocumentsPath`, `getLinuxDocumentsPath`, `StartupFolderUpdateRequest`, `StartupFolderUpdateResponse`, `platformDefaultPath`) — zero hits in source.
- **Test-coverage honesty**: independently re-ran both suites with coverage rather than trusting the prior report — confirmed genuine, not merely reported.
- **Implementation inefficiencies**: the extraction fully eliminated the targeted duplication; no O(n²) patterns or redundant git-subprocess calls introduced.
- **Native macOS wrapper**: grepped all Swift sources — no reference to the removed endpoint or any removed type.

No release-blocking correctness, security, performance, or accessibility issues found.
