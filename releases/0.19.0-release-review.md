# GitLocal v0.19.0 Release Review

## Scope

- Release: `v0.19.0` (MINOR).
- Release date: 2026-11-21
- Items: #139 (read aloud), PR #140.
- No new dependency.

## Summary of changes

- Read aloud for file previews: reads all of the preview or the selected text sentence by sentence, highlights the current sentence, reads headings on their own with longer pauses. Player bar with play/pause, previous/next sentence and heading, speed, voice picker. Ctrl+Alt+S start/pause, Esc stop; macOS app View menu "Read Aloud" / "Stop Reading".
- macOS: the local server speaks with `/usr/bin/say` (text on stdin, WAV out, async spawn, at most 2 jobs). Voice picker: System voice, recommended voices (Ava, Zoe, Serena, Evan, Nathan, Jamie) with install guidance, other installed English voices. Silent audio falls back to the System voice.
- Other platforms: Web Speech with on-device voices only.
- Content: Markdown/HTML, text, code comments, JSON, CSV, Excel, DOCX, PPTX (slides and notes), PDF, SVG.
- PDF previews gained a selectable text layer.
- New loopback-only routes: `GET /api/tts/voices`, `POST /api/tts/say`, `POST /api/tts/open-voice-settings`, `GET/PUT /api/read-aloud-preference`.

## Verification

- UI tests with coverage: 1131 pass, per-file thresholds met.
- New server tests pass with coverage at or above 90% (as root, the same 13 permission-based tests fail as on 0.18.1).
- `npm run lint`, `cd ui && npx tsc --noEmit`, `npm run build`: clean. CI `verify` passed on PR #140.
- Built app in Chromium with stubbed local Web Speech voices: Markdown, PDF, PPTX and DOCX read in order with the highlight advancing.

## Known limitations

- `say` output format flags, `say -v '?'` parsing on real output, the Spoken Content settings URL, and audio playback in the macOS app's WKWebView were not checked on a Mac before release.
- Siri voices are used only when Siri is the System voice [likely].
