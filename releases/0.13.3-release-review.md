## Summary of changes

- **Web footer `gitlocal.dev` link**: `AppFooter.tsx` now renders a second `<a>` (same `app-footer-link` class, `target="_blank"`, `rel="noreferrer"` as the existing GitHub link) pointing to `https://gitlocal.dev`, labeled "gitlocal.dev" to stay visually distinct from the existing "GitLocal" (GitHub) link. Covered by a new `AppFooter.test.tsx` (both links' hrefs/attributes, year/version rendering, and the version-normalization/empty-version branch) — 100% statement/branch/function/line coverage.
- **macOS "About GitLocal" panel links**: `AppDelegate.swift` replaces the bare `orderFrontStandardAboutPanel(_:)` selector with a new `showAboutPanel(_:)` method that passes a link-attributed `NSAttributedString` as the standard about panel's `credits` option — two centered lines, "gitlocal.dev" and "GitHub: ehud-am/gitlocal", each carrying an `.link` attribute that AppKit opens in the default browser automatically. Keeps using the standard (not custom) About panel, consistent with the "thin macOS wrapper" constitution principle.
- **Coverage-gate gap closed**: `AppFooter.tsx` was previously absent from `ui/vitest.config.ts`'s coverage `include` list (same class of gap as spec 038's CSV/Excel viewers) — added, and now enforced at the 90%-per-file gate like every other covered component.
- **Dependency security bump**: `hono` → `4.13.7` (fixes 3 advisories: incomplete `toSSG()` path-traversal fix, unbounded `parseBody()` dot-notation nesting, query-parser fragment-handling differential) and `vitest`/`@vitest/coverage-v8` → `4.1.11` (fixes a `@vitest/mocker` path-traversal/arbitrary-file-read advisory via a transitive bump). All three are patch-version bumps with no major-version jump; no behavior change expected or observed.
- **Cloudflare hosting migration (US3, operational only)**: `gitlocal.dev`/`www.gitlocal.dev` DNS now resolves to Cloudflare (confirmed: `dig` returns Cloudflare anycast IPs, and `curl -I https://gitlocal.dev` returns `server: cloudflare`). `docs/CNAME` removed from the repo accordingly. No runbook or account-specific detail was committed anywhere, per explicit instruction — the migration steps were delivered conversation-only.
- **Version/changelog**: `package.json`/`package-lock.json` bumped to `0.13.3`; `CHANGELOG.md` updated with all four user-facing/operational changes above.

## Contrarian QA Review

A focused review of the diff against `origin/main` covering correctness, regression risk, security, and coverage honesty for both functional changes:

- **Footer link markup**: the new `<a>` reuses the exact same class/target/rel pattern as the pre-existing GitHub link; no new CSS, no layout risk. Test asserts both links independently by role/name, so a future regression swapping hrefs would fail loudly. No issue found.
- **About panel `credits` approach**: confirmed via Apple's `NSApplication.AboutPanelOptionKey` documentation that `credits` accepts an `NSAttributedString` and is rendered as scrollable rich text with working `.link` attributes in the standard panel — this is a supported, non-hacky use of the API, not an abuse of an undocumented side channel. `showAboutPanel(_:)`'s menu item has `target` explicitly set to the `AppDelegate` instance (unlike the previous bare-selector wiring, which relied on `NSApplication` itself already implementing `orderFrontStandardAboutPanel(_:)` in the responder chain) — necessary because the new selector isn't an `NSApplication` method GitLocal doesn't own. No dangling-target risk: `AppDelegate` is a long-lived singleton for the process's lifetime.
- **Dependency bump blast radius**: both bumps are patch-only (`4.12.23→4.13.7` within hono's `4.x`, `4.1.3→4.1.11` within vitest's `4.1.x`) — no major/minor jump, no config changes required, full test suite passes unchanged. Low regression risk.
- **`docs/CNAME` removal**: verified this doesn't affect anything else in the repo — grepped for other references to `docs/CNAME` or the `gitlocal.dev` custom-domain wiring in build/deploy scripts and found none; the file was purely GitHub Pages' custom-domain declaration, unrelated to the npm/Homebrew release pipeline this same version bump triggers.
- **Security**: no new attack surface from the footer/About changes (two static outbound links, both to fixed, hardcoded HTTPS URLs — not user- or server-controlled). The dependency bumps are pure security fixes.
- **Accessibility**: both new links are plain anchors/rich-text links with visible text content (not icon-only), consistent with the existing GitHub footer link's accessible-name pattern.

No release-blocking issues found.

## Known, Accepted Build Warnings

- Same pre-existing >500kB UI chunk warnings noted in prior releases (`pdf.worker.min`, `index`, `pdf`, `ExcelViewer`), all lazily loaded and not new to this release. Not a blocker.

## Residual Risk

- **macOS About panel click-through has not been performed by a human.** The implementation environment for this change had no screen-recording/accessibility access, so the panel's link rendering/click behavior was verified by code review and a successful Debug build only, not by driving the actual GUI. Low risk (standard AppKit API, straightforward attributed-string construction), but recommend a quick manual check.
- **Cloudflare hosting migration (US3) is partially, not fully, verified**:
  - `gitlocal.dev` confirmed resolving to Cloudflare and serving HTTP 200 with `server: cloudflare`.
  - `www.gitlocal.dev` currently **does not resolve at all** (DNS lookup failure at review time) — the `www` DNS record appears not yet created/propagated on the Cloudflare side. Not blocking for this npm/Homebrew release (unrelated systems), but the hosting migration itself is incomplete until this is fixed.
  - GitHub Pages' repository settings (`Settings → Pages`) still have `gitlocal.dev` configured as the custom domain; as a result, the native GitHub Pages URL currently issues an HTTP 301 redirect to `gitlocal.dev` rather than serving the site directly and independently, and GitHub Pages will likely regenerate `docs/CNAME` on its next Pages build unless this setting is cleared. Attempting to clear it via the GitHub API failed with a 422 ("Unable to commit CNAME because the Pages branch is protected") — `main`'s branch protection blocks GitHub's own automated commit for this. This requires the repository owner to clear the custom-domain field manually in the GitHub web UI; it is **not yet done** as of this release.
- Publication status: verification and contrarian QA complete on `main` at the `v0.13.3` cut commit, PR #80 merged. **Not yet tagged.** Tagging and pushing `v0.13.3` triggers `.github/workflows/publish.yml` (publishes to the public npm registry, builds and attaches a macOS artifact to a new GitHub release, pushes an updated cask to the external `ehud-am/homebrew-gitlocal` tap) — proceeding per explicit go-ahead already given for the full release cycle, including this irreversible step.
