# GitLocal v0.15.1 Release Review

## Scope

- Release: `v0.15.1` (PATCH).
- Theme: gitlocal.dev analytics switched to Vizoalica's static script tag (no signed-token endpoint).
- Release date: 2026-10-25
- Website and deploy workflow only. No app, server, UI, API or dependency change; the npm package and macOS app are rebuilt with the new version number only.

## Summary of changes

- `.github/workflows/deploy-website.yml` no longer vendors Vizoalica's dynamic-configuration Pages Functions (`/vizoalica/config.json`, `/vizoalica/ingest-token`), the `vizoalica-loader.js` loader, the generated `wrangler.toml`, or the `VIZOALICA_TOKEN_SECRET` Pages secret step. It now replaces the `<!-- vizoalica -->` marker in each deployed page with
  `<script defer src="$VIZOALICA_ENDPOINT/vizoalica.js" data-source="$VIZOALICA_WEBSITE_KEY" data-token-url="none"></script>`
  and deploys `docs/` with `wrangler pages deploy` (Wrangler 4.127.1, unchanged).
- Settings, each a secret or else a variable: `VIZOALICA_ENDPOINT`, `VIZOALICA_WEBSITE_KEY`, `CF_ACCOUNT_ID`, `CF_PAGES_PROJECT`; `CF_API_TOKEN` must be a secret. `VIZOALICA_ENDPOINT` must be an https origin with no path; `VIZOALICA_WEBSITE_KEY` must match `[A-Za-z0-9_-]{1,128}`. Both are written into HTML, so the step fails on anything else.
- Every page in `docs/` carries the marker exactly once (in `<head>`, where the loader tag was). The step fails if a page has none or more than one. The committed pages, and so the `ehud-am.github.io/gitlocal/` mirror, load no analytics.
- `docs/vizoalica.js` (self-hosted SDK copy) removed: the backend serves the SDK.
- `tests/integration/website-structure.test.ts`: checks the marker instead of the loader tag.

## Verification

- Workflow injection step run locally on a copy of `docs/` with sample values: 14 pages tagged, one tag each. A value with a quote, a missing value, and a re-run on already-tagged pages each fail with an error.
- Server tests with coverage (non-root): 492 passed, 1 skipped, thresholds met. `npm run lint`: clean.
- Not verified here: a live deploy and events arriving in the Vizoalica console [requires the repository secrets; check after merge via the workflow run and the console's Install page "Check now"].

## Follow-up for the operator

- The Vizoalica website must have **Require a signed token** off, and its allowed origins must include `https://gitlocal.dev` (and `https://www.gitlocal.dev` if served).
- The Cloudflare Pages project still holds the old `VIZOALICA_TOKEN_SECRET` Pages secret and Functions from the previous deploy until the next deploy replaces them; the secret can be deleted in the Pages project settings.
