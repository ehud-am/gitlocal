# GitLocal v0.13.7 Release Review

## Scope

- Release: `v0.13.7` (PATCH), branch `claude/next-feature-gfggtk`, PR #108.
- Theme: terminal experience, from user feedback (margins, typing lag, arrow keys/history,
  copy/paste) plus a full terminal code review and QA cycle.
- Release date: 2026-09-26

## Summary of changes

- **Typing lag (root cause: server).** The UI polls `/api/sync` every 3 s. `getSyncStatus` ran
  about 11 `spawnSync` git calls (4x `git status -uall`) plus, per changed file, a full
  `ls-files` and a stat of every tracked file. All of it blocked the one Node event loop that
  also carries PTY/WebSocket I/O. Measured on a 5,000-file repository with 40 changes: 2.4 s
  per poll; keystroke echo max 2441 ms before, 143 ms after (browser, same machine).
  - `withGitOutputCache` (`src/git/repo.ts`): prefetch the expensive git commands with async
    `spawn`, then run the unchanged synchronous code with every git read memoized.
  - `getSyncStatusAsync` (`src/services/repo-watch.ts`), used by `src/handlers/sync.ts`.
  - `classifyChangedEntries`: one pass for all changed files instead of one `ls-files` per file.
  - `git ls-files -z`, `git check-ignore -z --stdin`, `GIT_OPTIONAL_LOCKS=0` on background reads.
- **Margins.** Padding moved to the tab wrapper in `TerminalPanel.tsx` (FitAddon measures the
  xterm container's parent, so padding there would be counted as grid space).
- **Arrow keys / history.** Removed xterm `convertEol` (rewrote LF to CR LF, misplacing the cursor
  on line-editor redraws); `TERM=xterm-256color`, `COLORTERM=truecolor`, UTF-8 `LANG` fallback
  (`buildPtyEnv`); clicking a tab focuses its terminal.
- **Copy / paste.** Input split into 8192-char frames (server `maxPayload` is 64 KB; a larger
  paste used to close the socket). Shortcuts in `terminal-shortcuts.ts`: Ctrl+Shift+C/V
  everywhere, Ctrl+C with a selection, Ctrl+V on Windows, Cmd+K clear on macOS.
- **Reconnect.** `terminal-connection.ts`: reconnect with backoff (250 ms to 8 s, 5 attempts),
  queued input up to 64 KB, resize sent only on grid change, server replay frames flagged
  `replay: true` and redrawn in place of the stale screen.
- **Security.** Terminal HTTP routes and the WebSocket upgrade require a loopback Host and
  Origin (`src/terminal/request-origin.ts`); session creation requires a JSON content type.
- **Replay buffer.** Chunked output buffer with an exact 200,000-char cap
  (`src/terminal/session-manager.ts`) instead of string re-concatenation per chunk.

## Contrarian QA review

Three independent passes (server, UI, accessibility) against the full diff, each assuming the
release was broken.

### Server findings

| # | Finding | Disposition |
|---|---------|-------------|
| S1 | BLOCKER (introduced on this branch, not in main): tracked files with non-ASCII names dropped from the Changes list (`ls-files` output C-quoted without `-z`) | Fixed: `ls-files -z`; regression test with `café.md`, `tab"q.md`, `dir ü/x.md` |
| S2 | `check-ignore` newline-delimited, and run for every changed path | Fixed: `-z --stdin`, only unindexed non-untracked candidates |
| S3 | Prefetch wasted when viewing a non-working-tree branch | Fixed: prefetch skipped; test added |
| S4 | Background `git status` could take the index lock and race a user's git command | Fixed: `GIT_OPTIONAL_LOCKS=0` |
| S5 | Two stats per tracked file in the working-tree revision | Fixed: one stat |
| S6 | Cross-origin page could create sessions with a CORS-simple POST | Fixed: JSON content type required (415 otherwise); session cap of 20 already present |
| S7 | Replay frame indistinguishable from live output | Fixed: `replay: true` flag |
| S8 | Remaining 50-220 ms stall per poll on the 5,000-file repository (synchronous compute part) | Follow-up; far below the reported 1-2 s |
| S9 | Rest of the API has no Host/Origin check | Pre-existing; follow-up |

### UI findings

| # | Finding | Disposition |
|---|---------|-------------|
| U1 | Ctrl+` from inside the terminal toggled twice (xterm handler and window listener), so nothing happened | Fixed: `stopPropagation`; unit test and browser check |
| U2 | Reconnecting to a session that had ended wiped the screen before learning it was gone | Fixed: screen replaced only when a replay arrives |
| U3 | xterm answered terminal queries found in replayed output, injecting junk into the shell | Fixed: input from xterm dropped while a replay is being parsed |
| U4 | `terminal.reset()` on reconnect raced output still queued for the old screen | Fixed: in-band RIS written ahead of the replay |
| U5 | Copy used only the async clipboard API (blocked on plain HTTP origins and in some WebViews) | Fixed: synchronous copy command first, clipboard API fallback; selection cleared only on success |
| U6 | Input past the 64 KB offline queue dropped mid-line, so a later Enter could run a partial command | Fixed: all input discarded until reconnect, with one notice |
| U7 | Enter/Space on a tab leaked into the newly focused terminal | Fixed: `preventDefault` |
| U8 | Key handling in `TerminalView.tsx` untested | Fixed: extracted `createTerminalKeyHandler`, unit tested |
| U9 | Platform-detection default test was tautological | Fixed: stubs the user agent |
| U10 | Padding area uses the panel background, not the terminal's | Left as is (matches the panel chrome) |

### Accessibility

- axe-core scan of main vs. this branch with the terminal open: no new
  violations. Pre-existing: `region` (panel content outside a landmark) and
  `scrollable-region-focusable` (code blocks); follow-ups.
- Connection notices were written only into the terminal grid, which screen readers do not
  announce. Fixed: a visually hidden `role="status"` live region in `TerminalView.tsx`.
