# GitLocal v0.13.6 Release Review

## Scope

- Release: `v0.13.6` — branch `045-community-participation`. Documentation, GitHub community
  configuration, and website copy only. **No application source (`src/`, `ui/`, `native/`) changed.**
- Release date: 2026-09-20
- Purpose: invite ideas, questions, bug reports, and code contributions through GitHub
  (Discussions + Issues) from the README, the npm listing, and gitlocal.dev.

## Summary of changes

- **GitHub repository settings (applied via API, not versioned in git):** Discussions enabled
  (default categories Ideas, Q&A, Show and tell, Announcements, General, Polls); private
  vulnerability reporting enabled.
- **`.github/ISSUE_TEMPLATE/`**: `bug_report.yml` and `improvement.yml` issue forms in plain
  language, and `config.yml` that disables blank issues and routes open-ended ideas, questions,
  show-and-tell, and security reports to the right place. **`.github/PULL_REQUEST_TEMPLATE.md`**
  and **`SECURITY.md`** added (`SECURITY.md` also added to the npm `files` allowlist, matching
  `CONTRIBUTING.md`/`CODE_OF_CONDUCT.md`).
- **`CONTRIBUTING.md`**: new "Ways to Take Part" section listing four participation levels (use it
  and give feedback, share ideas, report bugs, build), placed before the code-change rules.
- **`README.md`**: Discussions badge, a "Community" line at the top, a "Help Shape GitLocal"
  section, and a rewritten bottom "Contributing" section.
- **`packaging/npm/README.md`**: the same ask, with absolute URLs. This is a *separate* file: the
  npm `prepack` hook swaps it in for `README.md`, so editing only `README.md` would have left the
  npm listing unchanged. Guarded by a new assertion in `tests/integration/npm-package-contents.test.ts`.
- **gitlocal.dev (`docs/`)**: "Built in the open" section, Community nav link, Discussions footer
  link, and a new FAQ entry mirrored in the JSON-LD `FAQPage` (visible and structured FAQ counts
  both 8); `llms.txt` gains a Community section.
- **Corrected stale copy found during README review:** the README, site, and `llms.txt` still
  described a bottom-only terminal with Claude/Codex tab kinds (changed in 0.13.5).

## Verification

- `npm run verify`: 462 server tests + 591 UI tests pass, 0 audit vulnerabilities, build succeeds.
  One server test (`folder.test.ts` "returns no parent path when browsing the filesystem root")
  timed out once under full-suite load on the first run (26s, against a 5s limit), passed alone in
  ~0.5s, and the full suite then passed cleanly on rerun. Unrelated to this change; noted as a
  possible load-sensitive flake.
- Every GitHub URL added to the README, CONTRIBUTING, SECURITY, site, `llms.txt`, and templates
  returns HTTP 200 (checked with `curl`, after Discussions and vulnerability reporting were enabled).
- Issue-form YAML parses; JSON-LD parses; site rendered locally at desktop width and the new section
  visually confirmed. Mobile width could not be confirmed pixel-accurately (the headless browser's
  minimum window width clips the whole page, existing sections included); the new cards reuse the
  existing card styles and collapse to one column at the existing 860px breakpoint.

## Contrarian QA review

Per Constitution Principle VIII. **Performed inline by the release author, not by independent
sub-agents**, since the change set is documentation and configuration with no runtime code. Angles
attempted, assuming something is broken:

1. *Does the npm listing actually change?* Found that it would **not**: npm publishes
   `packaging/npm/README.md`, not `README.md`. Fixed, with a regression test. (Real finding.)
2. *Do promised things exist?* The bug form originally told users to run `gitlocal --version`, which
   does not exist in `src/cli.ts`. Replaced with the footer version. (Real finding.)
3. *Dead links / wrong category slugs?* All URLs checked; category slugs read from the GitHub API.
4. *Site and structured data disagree?* FAQ entry added to HTML, JSON-LD, and `llms.txt`.
5. *Contradiction with the local-first stance?* Copy states plainly that participation needs a free
   GitHub account while GitLocal itself needs none.
6. *Regression risk to the app or package?* No source changes; tarball contents verified with
   `npm pack --dry-run` (30 files, adds `SECURITY.md`).

No open blockers.
