# GitLocal v0.13.8 Release Review

## Scope

- Release: `v0.13.8` (PATCH). Feature PR #111 (merged), pre-release QA on branch
  `claude/multi-tab-view-ys3b5i`.
- Theme: multi-tab main view (spec `049-multi-tab-main-view`, issue #110).
- Release date: 2026-09-30

## Summary of changes

- **Tabs in the main view.** The landing folder view is unchanged. Opening a file adds a tab strip
  with a permanent folder tab and one closable tab per open file (`ContentTabStrip.tsx`, pure
  helpers in `ui/src/lib/file-tabs.ts`). Closing the last file tab returns to the last-browsed
  folder. `selectedPath` in `App.tsx` stays the single source of truth; one effect turns every file
  selection into an open/activated tab.
- **Layout.** Repository block, then tab strip, then content card (review feedback on #111).
- **Removed** the file view's "Back to folder" button (the folder tab and the tree replace it).
- **Persistence.** Open tabs are repeated `tab` URL parameters (cap 50).
- **Cleanup.** Tabs close on in-app file/folder delete, sync-detected missing file, and
  branch-switch fallback; cleared on any repository-root switch.
- No server or API change; both distributions share the UI.

## Contrarian QA review

One pass over the full feature diff, assuming it was broken, plus an accessibility scan.

| # | Finding | Disposition |
|---|---------|-------------|
| Q1 | Tabs cleared only by the launch-time repository-mismatch reset. A startup open target or a macOS open-file event in another repository set the new root first, so the mismatch never fired and the old repository's tabs stayed | Fixed: a `viewerRepoPath` effect clears tabs on any root change, declared before the tab effect so the newly opened file keeps its tab; test added |
| Q2 | Pre-existing (also on `main`): opening a file from another repository while running (macOS Finder) showed the new repository's root without the file. `applyAcceptedOpenTarget` changed the root while `info.path` was stale, and the mismatch reset then cleared the selection | Fixed: refetch repository info before applying the open result; test asserts the file is fetched and its tab active |
| Q3 | Strip could render during the startup open-target fetch or a repository mismatch with the folder tab marked active over content about to be replaced | Fixed: strip hidden while either is pending |
| Q4 | Unsaved-changes dot on the close button was visual only; the accessible name stayed "Close X" | Fixed: name becomes "Close X (unsaved changes)" |
| Q5 | Parent Folder explanatory comment separated from its constant by the new `showContentTabs` line | Fixed |
| Q6 | `localOnly` is not persisted per tab; restored tabs show without the local badge until reopened from the tree | Accepted: display only for files |
| Q7 | Tabs from a previous branch are only checked when activated (then closed by the missing-file reconciliation) | Accepted, documented in the spec edge cases |
| Q8 | Per-tab scroll position and raw/preview toggle reset on tab switch | Accepted, out of scope in the spec |

### Accessibility

- axe-core on the built app: landing `scrollable-region-focusable` (2 nodes), tabs open
  `scrollable-region-focusable` (1 node). Both pre-existing (code blocks); the strip adds no
  violation. jest-axe on `ContentTabStrip`: none.
- WAI-ARIA tabs pattern: `role="tab"`, `aria-selected`, roving `tabindex`, Left/Right/Home/End,
  Enter/Space, Delete/Backspace to close.
