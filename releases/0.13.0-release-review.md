## Summary of changes

- **PPTX preview**: `.pptx` files render each slide as a best-effort formatted view (positioned text, background fill, embedded images) with next/previous navigation and a speaker-notes panel, via lazily-loaded `jszip` + `fast-xml-parser`, replacing the previous binary-file fallback. Registered through the existing preview-registry pattern with zero `ContentPanel.tsx` dispatch changes. Pixel-faithful rendering intentionally out of scope (no free/license-compatible renderer exists).
- **Security/correctness/reliability fixes** (all shipped in `2f2cca1`): repo write-path containment now re-verifies every intermediate path segment (and immediately before `mkdir`/`writeFile`), closing a symlink write-escape gap; branch-search file-path parsing now strips a length-based `${branch}:` prefix instead of splitting on `:`, fixing filenames containing a colon; the changed-files review panel now reads `git status --porcelain=v1 -z` (NUL-delimited) instead of the newline-delimited default, correctly handling renamed paths with spaces/non-ASCII/quotes without decoding Git's C-quoting; non-terminal WebSocket upgrade attempts are now closed promptly instead of left open.
- **"Empty folder on launch" fix** (`8f0ad4f`, `902c7c1`): a repo path that's been deleted, renamed, unmounted, or turned unreadable previously rendered as a normal, silently-empty folder. `resolveGuaranteedFallbackPath` (`src/services/startup-preferences.ts`) now provides a verified-readable fallback chain (Documents → home → cwd → OS temp dir → filesystem/drive root), wired into startup (`initializePaths`), a mid-session self-heal at the top of `infoHandler`, and `repositoryParentFolderHandler` (walks past an unreadable ancestor). A new `'safe-fallback'` `StartupFolderSource` surfaces a clear on-screen banner via the existing picker-page mechanism. `902c7c1` addressed 7 findings from an internal deep-review pass on this code before it reached this release review.
- **Pre-release hardening** (`1a1ddba`, this review): bumped `fast-xml-parser` `^4.5.7` → `^5.11.1` to clear a moderate npm audit finding (`GHSA-gh4j-gqv2-49f6`, an `XMLBuilder` XSS/injection issue — GitLocal's `PptxViewer.tsx` only uses `XMLParser`, so the vulnerable code path was never reachable, but the bump keeps the audit clean); `npm audit fix` also picked up a `browserslist` bump for an unrelated high-severity advisory. Corrected two comments in `src/handlers/repo.ts` that inaccurately claimed window-refocus retriggers the self-heal fetch (the UI disables focus-based refetching globally — `ui/src/main.tsx`).

## Contrarian QA Review

An independent adversarial review of the full change set (all 4 pre-existing commits plus the diffs) examined: PPTX-viewer XSS risk (text is JSX-interpolated, never `dangerouslySetInnerHTML`; inline styles are set via property objects, not string-concatenated CSS — no injection path), embedded-image path handling (resolved only against the in-memory JSZip entry table, no filesystem access, so the on-disk containment model doesn't apply and isn't needed), ReDoS risk in new parsing (none found), accessibility (PPTX slide nav lacks an `aria-live` announcement on slide change — a real but minor gap, consistent with existing preview components such as PDF/CSV which have the same gap, so not a new regression), and dead code (none found).

Two findings were raised and addressed:
- **Comment accuracy**: `recoverIfRepoPathUnavailable`'s doc comments claimed "the next window refocus" retriggers the self-heal fetch, which is false — the UI disables focus-based refetching globally (`ui/src/main.tsx`). **Fixed in `1a1ddba`** (comment-only change, no behavior change).
- **Residual risk, not fixed**: the startup-folder banner query (`['startup-folder']`) is only invalidated alongside `['info']` in the manual-Refresh path. The one other place `['info']` is invalidated outside that path (the "Try again" action on the info-fetch error screen) is a distinct failure mode — a network/server error on `/api/info` itself, not the unreadable-repo-path self-heal — so this gap isn't reachable through today's code paths. Flagged here as a fragility to watch if a future change adds another `['info']` invalidation without pairing it with `'startup-folder'`.

No release-blocking correctness, security, or performance issues found.

## Residual Risk

- The `['startup-folder']`/`['info']` invalidation-pairing fragility noted above under Contrarian QA — not reachable today, worth a follow-up guard if the query-invalidation surface grows.
- PPTX slide navigation lacks an `aria-live` region for screen-reader announcements on slide change — pre-existing gap pattern shared with PDF/CSV viewers, not new to this release; not treated as a blocker.
- Native macOS Swift code is untouched by this release.
- Publication status: verification and contrarian QA complete on `039-bugfix-pptx-preview`. **Not yet merged to `main` or tagged.** Merging and tagging `v0.13.0` triggers `.github/workflows/publish.yml` on push, which publishes to the public npm registry, builds and attaches a macOS artifact to a new GitHub release, and pushes an updated cask to the external `ehud-am/homebrew-gitlocal` tap. That trigger step is pending explicit go-ahead given its blast radius (public, cross-repo, effectively irreversible once published).
