## Pre-Release Contrarian QA (this review)

Per Constitution Principle VIII, three independent contrarian-QA sub-agents reviewed the full `035-quality-hardening` vs `main` diff ahead of this release, each assuming regressions exist rather than presuming readiness: one covering bugs/security, one covering performance/dead-code, one covering accessibility. Each was briefed to focus on Phases 5-8 (the work not covered by the superseded interim review) to avoid re-litigating already-reviewed ground.

**Findings, both fixed before release:**

1. **[Accessibility regression, fixed]** Phase 8's PK-009 fix changed the folder picker's sidebar rows from `role="tree"`/`"treeitem"` to `role="listbox"`/`"option"` to better match their actual flat, non-hierarchical behavior. This traded one problem for a worse one: `listbox`/`option` carries a *required* WAI-ARIA APG keyboard contract (arrow-key movement, Enter/Space activation) that was never implemented, so screen readers were told the widget supported interactions it didn't support any better than before. **Fix**: removed the `listbox`/`option` roles entirely; each row is now a native `<button type="button">` (matching the main table view's existing button pattern), with `aria-current` reflecting the selected row. Buttons are natively focusable and keyboard-activatable via Tab + Enter/Space with no custom key handling needed — a genuine improvement over `main`, where the equivalent rows had no keyboard support at all (`role="tree"`/`"treeitem"` with no `tabIndex`). Container role changed to `role="group"` (no interaction contract, stays a stable labeled anchor). `PickerPage.test.tsx` updated to match (45/45 passing). See `specs/035-quality-hardening/findings/ui-picker.md` Adjudication Log for full detail.
2. **[Unfixed inefficiency + inaccurate record, fixed]** The Checkpoint G2 findings log claimed FT-002 (an effect re-running on every unrelated `nodeStates` change) was fixed by switching the effect body to read a ref. In fact only the effect *body* was changed; the dependency array still listed `nodeStates`, so the effect kept re-running on every state change exactly as originally described — not a functional bug (the internal expanded/children/error guard still prevented redundant network calls) but a real, low-impact inefficiency and a documentation error. **Fix**: removed `nodeStates` from the effect's dependency array in `FileTree.tsx`, with a comment noting the ref-based read is intentional. See `specs/035-quality-hardening/findings/ui-file-tree.md` Adjudication Log for full detail.

**No other issues found.** All three agents' full reports were reviewed; everything else raised was either already covered by the existing findings/adjudication record, a disclosed and accepted trade-off (e.g. Swift changes verified by manual review only, no toolchain available in this environment — a pre-existing, disclosed project constraint), or not a real issue on inspection (e.g. an initial over-flagging of PK-009 as "no keyboard nav at all," which was accurate pre-fix but is resolved by finding 1 above). No new bugs, security issues, or dead code were introduced by Phases 5-8; `npx knip` (root and `ui/`) matches the established baseline with no new findings, both before and after the two fixes above.

## Accessibility Review

- Existing `jest-axe` coverage across every touched component (App, FileTree, PickerPage, RepoContextHeader, ContentPanel, BranchSwitchDialog, TerminalPanel, SearchPanel) confirms 0 violations post-change.
- File tree (FT-010): closes a real pre-existing ARIA APG gap — full keyboard navigation (arrow keys, Enter/Space, roving tabindex) added where none existed before.
- Folder picker sidebar: closes a real pre-existing gap and a self-introduced regression (see Pre-Release Contrarian QA finding 1) — rows are now natively keyboard-operable, an improvement over `main`.
- Picker directory rows no longer falsely announce "collapsed" to screen readers (FT-011, from the original interim release).
- Two low-severity, pre-existing gaps remain and are explicitly deferred (unchanged from the interim review): no Home/End key support in the file tree, no `aria-level`/`aria-setsize`/`aria-posinset` on tree items. Neither is a WCAG requirement; both are documented as future enhancements, not release blockers.
- `jest-axe`'s static rule coverage cannot detect a missing keyboard-interaction contract (exactly how the PK-009 regression reached the branch) — this gap was closed for this release by dedicated human-directed contrarian QA, per Constitution Principle VIII's explicit accessibility-testing requirement, rather than by automated coverage alone.
