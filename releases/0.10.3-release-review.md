# GitLocal v0.10.3 Release Review

## Scope

- Release: `v0.10.3` — an **interim** cut of the `035-quality-hardening` epic, covering Phase 3 in full (US1: a systematic architecture/code review of all 15 reviewable units, 110 findings logged) and part of Phase 4 (US2: bug fixes) — Checkpoint B1 (6 findings) and Checkpoint B2 (6 findings), 12 fixed in total — plus a standalone, user-requested fix pinning the file-view header above scrollable content. **Phase 4 Checkpoint B3 and Phases 5-8 (dead code removal, duplicate-code consolidation, efficiency, and readability polish) are not part of this release** and remain outstanding on the branch.
- Branch: `035-quality-hardening`, 15 commits ahead of `origin/main`. 56 files changed, 3440 insertions(+), 139 deletions(-).

## Summary of changes

- **Phase 3 (US1)**: Full architecture/code review across all 15 units (server-git, server-handlers, server-root, server-terminal, server-services, ui-app-shell, ui-content-panel, ui-types, ui-services, ui-repo-context, ui-terminal-panel, ui-picker, ui-search, ui-file-tree, native-macos), producing `architecture-review.md` and 110 logged findings (16 bug, 18 dead-code, 27 duplicate, 21 efficiency, 28 readability). Two units (`App.tsx`, `ContentPanel.tsx`) were explicitly evaluated against and cleared of "god component" concerns. No product code changes in this phase — review/documentation only.
- **Phase 4 Checkpoint B1** (T051-T056, 6 fixes): NM-001 (macOS service-lifecycle race condition), NM-004 (macOS JS-injection via unescaped filenames), ST-001 (stale server-side terminal error-code type), SV-001 (sync status misreporting directory/missing paths as files on non-current branches), RC-008 (dead `syncActionLabel` prop threading), FT-010 (file tree missing keyboard navigation).
- **Phase 4 Checkpoint B2** (T057-T062, 6 fixes): FT-011 (Picker directory rows always announcing "collapsed" regardless of state), NM-002 (macOS process shutdown never escalating to SIGKILL, non-blocking), NM-011 (macOS bundle-path fallback resolving against cwd instead of the app bundle), SH-007 (opened-file name mismatch outside git repos, using the raw pre-canonicalization path), SV-003 (uncaught-exception startup crash risk when home directory is unreadable), UT-003 (`ViewerState` naming collision between server-dead and UI-active types, coordinated with the server-side dead-interface removal).
- **Standalone fix** (user-requested, outside the phased checklist): the file view's name/action-button header (Back to folder, Find in file, Copy, file-actions menu) now stays pinned at the top of the panel while content scrolls, in both view and edit mode — previously it scrolled away with the file content on large files.
- **Pre-release QA fixes** (this review, see below): memoized `FileTree`'s visible-order tree walk to stop duplicating render-pass work on every render (also fixes unbounded growth of a stale parent-path map); removed a dead `getRepoSyncActionLabel` export and its leftover test/mock references, orphaned by RC-008's prop removal.

## Contrarian QA Findings

A dedicated contrarian-QA sub-agent reviewed the full `035-quality-hardening` vs `main` source diff (`src`, `ui/src`, `native/macos`; specs/docs/tests excluded), assuming regressions exist rather than presuming release-readiness, across bugs, performance, security, accessibility, dead code, and implementation quality. Actionable findings were fixed before this release; the rest are documented below as accepted, non-blocking.

1. **[Medium, fixed]** `FileTree.tsx`'s new roving-tabindex support (FT-010) added a `computeVisibleOrder` tree walk that duplicated `renderNodes`' own filtering pass on every render, unmemoized. Fixed by wrapping the walk in `useMemo`, keyed on the same inputs that can actually change the visible set (`roots`, `nodeStates`, `generatedLocalVisibility`, `hideDotfiles`, `selectedPath`); as a side effect this also fully rebuilds the parent-path map each time instead of incrementally patching it, closing the low-severity stale-entry issue below in the same change.
2. **[Low, fixed]** The same tree-walk's `parentOf` ref map only ever added/refreshed entries for currently-visible nodes, never pruning entries for nodes that become invisible (parent collapsed, filtered out) — unbounded growth over a long session with heavy expand/collapse. Fixed for free by the `useMemo` rewrite above, which rebuilds the map from scratch on every recompute rather than patching it in place.
3. **[Low, fixed]** `getRepoSyncActionLabel` (`ui/src/lib/sync.ts`) was left behind as a dead export after `RepoContextHeader`'s `syncActionLabel` prop was removed (RC-008) — still referenced only by its own test and a stale mock prop in `App.logic.test.tsx`. Removed the export, its dedicated test block, and the leftover mock prop/import.
4. **[Low, accepted]** No `Home`/`End` key support in the file tree's new keyboard navigation (jump to first/last visible node) — a common ARIA tree-pattern convenience, not a WCAG requirement. Consistent with the project's own findings doc already flagging this implementation as "not fully APG-complete." Deferred as a future enhancement rather than a release blocker.
5. **[Low, accepted]** No `aria-level`/`aria-setsize`/`aria-posinset` on file tree items — pre-existing gap, not introduced by this branch, though this branch did touch the same ARIA surface for FT-010. Deferred alongside finding 4.
6. **[Low, accepted]** Swift `stop()`'s SIGTERM→SIGINT→SIGKILL escalation (NM-002 fix) blocks the calling thread for up to ~3s worst case if a child process is wedged, versus the prior fire-and-forget behavior. This is a deliberate, tested trade-off (see `native/macos/GitLocalTests/LifecycleTests.md`) favoring guaranteed cleanup over instant-return; well-behaved children (the common case) exit within the first ~50ms poll tick.
7. **[Positive]** `ViewerWindowController.swift`'s switch from manual JS-string escaping to JSON-encoding (NM-004) closes a real injection gap: the old code only escaped `\` and `'`, so filenames containing `"` or other JS-meaningful characters could break out of the intended string literal.
8. **[Positive]** `src/handlers/repo.ts`'s `basename(resolvedInputPath)` fix (SH-007) uses the already-canonicalized, validated path rather than raw client input — strictly safer than before, not a new attack surface.
9. **No blocking issues identified.** Nothing in this diff regresses correctness, introduces a security hole, or breaks accessibility relative to `origin/main`; on all three fronts this branch is a net improvement.

## Accessibility Review

- Existing `jest-axe` coverage on every touched component confirms 0 violations post-change, including `FileTree.test.tsx` (new roving-tabindex and keyboard-activation cases) and `PickerPage.test.tsx` (updated `aria-expanded` regression test).
- FT-010 closes a real ARIA APG gap: the file tree's `role="tree"`/`role="treeitem"` widget previously had no `tabIndex`/keyboard handling at all (mouse/pointer only); it now supports ArrowUp/Down/Left/Right, Enter/Space activation, and roving tabindex.
- FT-011 removes a misleading hardcoded `aria-expanded={false}` on all Picker directory rows (previously always announced "collapsed" regardless of real state, since the Picker's sidebar tree has no real expand/collapse state) — the fix removes the attribute rather than driving it with fake state, which is the correct resolution for a widget with no real expand/collapse behavior.
- Two low-severity, pre-existing-pattern gaps remain and are explicitly deferred (see Contrarian QA findings 4 and 5 above): no Home/End key support, no `aria-level`/`aria-setsize`/`aria-posinset`.
- No color/contrast changes were introduced by this branch.
