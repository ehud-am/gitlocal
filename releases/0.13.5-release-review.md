## Summary of changes

- **Removed the Claude/Codex terminal-tab kind concept** (User Story 1): every terminal tab is
  now a plain shell. Deleted `src/terminal/cli-detection.ts` (kept only its unrelated
  `isPtySupported` check, moved to a new minimal `src/terminal/pty-support.ts`) and
  `ui/src/components/TerminalPanel/TerminalKindSelect.tsx`; removed `TerminalKind`, the `kind`
  field, `TerminalCapabilities.claudeCliFound`/`.codexCliFound`, the `cli_not_found` pre-flight
  503 path, and the server-side auto-launch write, from both the server (`src/terminal/types.ts`,
  `src/terminal/session-manager.ts`, `src/handlers/terminal.ts`) and the UI
  (`ui/src/types/index.ts`, `ui/src/hooks/useTerminalPanel.ts`,
  `ui/src/components/TerminalPanel/*`). The now-unused `/api/terminal/capabilities` route and its
  handler/UI client method (`terminalApi.getCapabilities`, confirmed to have no callers) were
  removed outright rather than kept as dead code.
- **Configurable dock position** (User Story 2): a new server-side preference,
  `~/.gitlocal/terminal-panel-preference.json` (`src/services/terminal-panel-preference.ts`,
  mirroring `src/services/startup-preferences.ts`'s pattern), exposed via
  `GET`/`PUT /api/terminal-panel-preference`, lets the panel dock to `bottom`/`left`/`right`
  (default `right`) and persists across restarts. `TerminalPanel.tsx` was reworked to be
  orientation-aware (height/row-resize for bottom, width/col-resize for left/right); `App.tsx`
  wraps the app-body region and the panel in a single always-present flex container whose
  direction and `order-first` class toggle with the position — the panel is never unmounted by a
  position change, so open tabs/sessions/scrollback survive it (FR-006).
- **Unified "New Terminal" control** (User Story 3): `NewTerminalButton.tsx` replaces the old
  kind-selector-plus-create pairing with one consistently labeled action used identically in the
  empty state and the tab strip. Also fixed a real, user-visible labeling bug found during
  implementation: tab numbering previously derived from `tabs.length` at insertion time, so
  closing "Terminal 2" and opening a new tab could silently reuse the number 2 for a different
  session — `useTerminalPanel.ts` now uses a monotonic per-panel counter (`nextOrdinalRef`) so a
  tab number is never reused within a session.
- **Version/changelog**: `package.json`/`package-lock.json` bumped to `0.13.5`; `CHANGELOG.md`
  updated with all three changes in user-facing language.

## Contrarian QA Review

An independent sub-agent review (fresh context, no access to this session's reasoning) examined
the full uncommitted diff plus all newly-added files for correctness bugs, regressions/dangling
references across the whole repo (including `native/macos/`), accessibility, security, dead
code, layout-CSS correctness (reasoned through by hand rather than assumed), and test-quality
(tautological-assertion check). It independently re-ran both test suites and both type checks
rather than trusting this session's report.

Findings raised and their disposition — **all three addressed** prior to release:

- **Non-hermetic test** (`tests/unit/services/terminal-panel-preference.test.ts`, the "falls back
  to the home-directory default" case): it called `readTerminalPanelPreference()` with the env
  var unset, silently relying on the real `~/.gitlocal/terminal-panel-preference.json` not
  existing on the machine running the test — a real flakiness risk on any dogfooded dev/CI
  machine that has actually used this feature. **Fixed**: the test file now mocks `node:os`'s
  `homedir()` to a freshly created temp directory for that one case, so it never touches the real
  home directory regardless of the machine's state.
- **Test-hygiene / temp-dir leak** (`tests/unit/handlers/terminal.test.ts`'s new
  `'terminal panel dock-position preference'` describe block): `beforeEach` created a temp
  directory with no matching cleanup. **Fixed**: added an `afterEach` that removes it. While
  fixing this, also found and fixed a related latent bug the QA pass didn't explicitly name but
  that its structural review surfaced: `previousPreferencePath` was being captured fresh in every
  `beforeEach` (so it captured the *previous test's* temp path, not the true pre-suite value),
  meaning the final `afterAll` restore would leave the env var pointed at a deleted temp
  directory instead of its original value/unset state. Now captured once, outside any hook.
- **Accessible-name/visible-text mismatch** (`ui/src/components/TerminalPanel/NewTerminalButton.tsx`):
  `aria-label` stayed `"New Terminal"` even while the visible text switched to `"Starting
  terminal…"` during creation, so a screen-reader user got no indication of the busy state that a
  sighted user could see. **Fixed**: `aria-label` now matches the visible text
  (`creating ? 'Starting terminal…' : 'New Terminal'`); the one test asserting the busy state was
  updated to query by the new accessible name.

Explicitly ruled out by the review (see its full report for detail): no dangling
`TerminalKind`/`TerminalCapabilities`/`cli-detection`/`/api/terminal/capabilities` references
anywhere in `src/`, `ui/src/`, or `native/macos/` Swift code; no path-injection surface in the
new preference file writer (`dockPosition` is enum-validated before ever reaching
`writeFileSync`, and the file path is never user-controlled); the dock-position flex/`order-first`
CSS and the mouse-drag/ArrowKey resize sign math were traced by hand and are internally
consistent for both side-dock directions; the new/updated tests are not tautological (e.g. the
monotonic-tab-numbering fix has a genuine regression test, and the `FR-006`
session-preservation test asserts a real invariant — `TerminalView` mount count staying at 1
across a position change — rather than a fake one).

No release-blocking correctness, security, performance, or accessibility issues remain open.

## Residual Risk

- All contrarian-QA findings above have been fixed and re-verified (both suites green, both type
  checks clean, after the fixes). No open findings remain.
- This review environment cannot drive a live browser or the native macOS app's GUI, so the
  actual on-screen appearance of the three dock positions, the resize-handle drag feel, and the
  native macOS "Toggle Terminal" menu item's continued behavior have **not** been visually
  confirmed by a human. Server-side API behavior and all UI logic/layout branches are covered by
  the automated test suites (which do assert on rendered CSS classes and ARIA orientation for all
  three positions) and by manual `curl`-level verification of the new endpoints, but a quick
  visual pass in a real browser (and, for the native app, `GitLocal.app`) before or shortly after
  release is recommended.
- Publication status: implementation, verification, and contrarian QA are complete on
  `044-simplify-terminal-panel`, and the branch is being committed locally now. **Not yet pushed,
  merged to `main`, or tagged** — this review does not include a push/publish step; that remains
  a separate, explicitly-confirmed action given the `publish.yml` workflow's blast radius (public
  npm publish, GitHub release + macOS artifact, Homebrew cask update on push of a version tag).
