## Contrarian QA Findings

Contrarian QA sub-agent reviewed the full diff since the last release (`0.9.13` → `main`) against `specs/030-navigation-improvements/spec.md`:

- Sync badge ("Up to date") is suppressed whenever local changes are present, even though commit-sync state and working-tree state are orthogonal facts.
  - Result: Accepted for this release. This is the intended, tested design (mutually-exclusive tags per the original request), not a defect; revisit only if users report wanting both facts visible at once.
- The "info"-toned tag (used for the local-changes count, now more prominent since it moved out of the removed status-summary box into the always-visible tag row) failed WCAG AA text contrast in dark mode: 3.21:1 against a 4.5:1 requirement.
  - Result: Fixed. Changed the tone's text color mix target from a fixed `black` to the theme-aware `var(--foreground)`, raising dark-mode contrast to 4.62:1 while keeping light mode at 5.04:1 (both AA-compliant). See `ui/src/components/ui/meta-tag.tsx`.
- `CHANGELOG.md`'s `Unreleased` section still described the button as "Home" after the polish pass renamed it to "Root".
  - Result: Fixed as part of this release's changelog entry.
- Stale "Home" wording in a test title and local variable names in `App.test.tsx` (assertions themselves correctly targeted "Root").
  - Result: Fixed. Cosmetic only, no behavioral risk.
- Git-repo-boundary logic (`classifyLocalPath` / `getContainingGitRoot`) correctly resolves the nearest enclosing repository for nested sub-repositories, and `Home`/`Readme` enablement correctly reflects filesystem-root and no-README states.
  - Result: No issue found.
- No leftover dead code from the removed `Breadcrumb` component or the removed duplicate Readme jump-link.
  - Result: No issue found.

No remaining release blocker was found after the dark-mode contrast fix.

## Accessibility Review

- `jest-axe` structural checks (`App.test.tsx`, `RepoContextHeader.test.tsx`) pass with 0 violations; these do not evaluate color contrast under JSDOM, which is why the dark-mode contrast issue above required manual review rather than being caught by the automated a11y suite.
- The three new toolbar buttons (Parent Folder / Root / Readme) are real `<button>` elements with matching `aria-label` and `title`, and correctly reflect disabled state at the filesystem root or when no README exists — an improvement over the removed breadcrumb's `role="link"` div items.
- The dark-mode contrast regression identified above is fixed (4.62:1, meets WCAG AA for normal-size text); light mode remains compliant (5.04:1).
