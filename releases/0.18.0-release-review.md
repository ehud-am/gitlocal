# GitLocal v0.18.0 Release Review

## Scope

- Release: `v0.18.0` (MINOR).
- Release date: 2026-11-08
- Items: #130 (folder navigation between Git and non-Git folders), #134 (Go to auto-complete). PR #135.
- No new dependency.

## Summary of changes

- Folder inside a repository: `resolveDirectoryOpenTarget` (`src/git/repo.ts`) roots it at the repository with the folder selected. Used by `repositoryOpenHandler` (picker, Go to), `initializePaths` (command line; reported through an accepted startup open target) and `repositoryParentFolderHandler`.
- Entering a repository: the UI reopens at the selection's absolute path when `/api/repo/location` reports a repository root other than the open root (plain folder -> repository, repository -> nested repository). The `repo-location` query key includes the open root.
- Parent Folder: always answers with a `rootPath`. The parent opens in the folder view, as the outer repository when inside one, otherwise as a plain folder. The picker is reached only when no readable parent exists. Only leaving a repository asks for confirmation.
- Folder actions: visible "New folder" button in the folder view and the picker; the folder view menu gains "Run git init" (plain folders) and "Clone into subfolder".
- Plain folders no longer show the repository dashboard; switching roots in place drops the previous root's Git query data.
- Nested repository README is read from its own branch, not the open repository's.
- `canonicalizeExistingPath` uses `realpathSync.native`, so a path typed in another letter case matches `git rev-parse --show-toplevel` [likely fix on macOS/Windows; not reproducible on Linux].
- Selection kept when GitLocal switches the root itself (`acceptedOpenRootRef`); the "different folder" reset could otherwise run after the new selection in a real browser.
- Go to auto-complete: read-only `GET /api/path/complete?input=` (`src/handlers/path-complete.ts`); combobox list in `GoToPathDialog.tsx` (Up/Down, Tab/Enter accept, Escape closes the list first).

## Verification

- Server tests: 518 pass as a non-root user; as root the same 13 permission-based tests fail before and after the change (environmental).
- UI tests with coverage: 1043 pass, per-file thresholds met (`App.tsx` branches 91.6%).
- `npm run lint`, `cd ui && npx tsc --noEmit`, `npm run build`: clean. CI `verify` green on PR #135.
- Chromium against the built app: plain folder -> repository -> subfolder in Git mode; Go to with completions; Parent Folder from a repository and from a plain folder; plain folder shows no repository cards.

## Known limitations

- Clicking into any nested repository (including a submodule or a clone under `node_modules`) switches the open root to it.
- File tabs are cleared when the open root changes.
- Escape pressed while completions are still loading closes the Go to dialog.
