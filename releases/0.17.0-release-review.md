# GitLocal v0.17.0 Release Review

## Scope

- Release: `v0.17.0` (MINOR).
- Release date: 2026-11-05
- Items: #98 Excel charts; DOCX comments (0.16.0 known gap); Vizoalica README pixel; dependency refresh.
- Deferred to a later release: #130 (navigation between git and non-git folders).
- No new dependency.

## Summary of changes

- Excel charts (#98): `ui/src/components/ContentPanel/xlsx/charts.ts` opens the workbook with `ooxml/package.ts` and walks workbook sheet -> sheet `drawing` -> drawing anchors (`twoCellAnchor`, `oneCellAnchor`, `absoluteAnchor`, including group shapes) -> `graphicFrame` -> chart part. Charts are parsed with the PPTX chart parser (`pptx/chart.ts`) and drawn with `pptx/chart-view.tsx`, using the workbook theme. Size comes from the anchor (default 64px columns and 20px rows for cell anchors, the extent otherwise, clamped to 160-1200px). Chart parts without `c:numCache`/`c:strCache` (openpyxl writes none) get caches built from the referenced cells (`fillMissingCaches`, resolver `resolveRangeFor` in `ExcelViewer.tsx` over the SheetJS workbook). Legacy `.xls` (not a zip) shows no charts. Chartsheets with a readable chart no longer show the "contains a chart" note.
- DOCX comments: `w:commentRangeStart`/`w:commentRangeEnd` mark text inside a range (`comment: true` on text inlines; ranges may span paragraphs), `w:commentReference` becomes a `commentRef` inline. `word/comments.xml` is read in order of first reference (`Comment`: number, author, date part of `w:date`, blocks). Rendered as a highlighted span, a `[n]` superscript link that scrolls to the comment, and a "Comments" region after footnotes and endnotes on the last sheet. Replies (`commentsExtended`) are listed as separate comments, not threaded.
- README pixel: `packaging/npm/readme-pixel.mjs` fills a `<!-- readme-pixel:start -->`/`<!-- readme-pixel:end -->` block (both READMEs, empty in the repository) with `![](<origin>/v1/pixel.gif?website=<key>&path=<path>)`, following Vizoalica's `docs/operations/pixel.md`. Inputs: `VIZOALICA_ENDPOINT` (origin only) and `VIZOALICA_PIXEL_WEBSITE_KEY`, else `VIZOALICA_WEBSITE_KEY`; key and path are pattern-checked, an incomplete setting leaves the block empty. GitHub README: the pixel line (path `/readme`, website from the Vizoalica console) is committed in `README.md`. A workflow that filled it on push to `main` was removed after merge: `main`'s ruleset requires the `verify` check, so its `GITHUB_TOKEN` push was rejected (GH013). npm README: the `prepack` hook fills the packed copy only, path `/npm/readme`; `publish.yml` passes the settings to `npm publish`.
- Dependencies: `hono` 4.13.13 -> 4.13.16, `@hono/node-server` 2.1.5 -> 2.1.6 (ranges raised; lockfile edited for these two entries only).
- Docs: gitlocal.dev previews page (Excel charts, Word comments, limitations).

## Verification

- Server tests: 502 run; the same 13 permission-based tests fail as root before and after the change (environmental). New `tests/integration/readme-pixel.test.ts`.
- UI tests with coverage: all passed, per-file thresholds met. `xlsx/charts.ts` 94.3% branches, `ExcelViewer.tsx` 92.7%.
- `npm run lint`, `cd ui && npx tsc --noEmit -p .`, `npm run build`: clean. `npm audit`: 0 vulnerabilities.
- Chromium against the built app: an openpyxl workbook with an embedded bar chart and pie chart; a python-docx document with a comment.
- `prepack`/`postpack` run locally with test settings: packed README gets the image, the committed README is restored.

## Setup needed outside the repository

- Vizoalica console: switch on the pixel for the website whose key is used. Vizoalica recommends a separate website for README counts, since anyone with the public key can request the image; set `VIZOALICA_PIXEL_WEBSITE_KEY` to use one.

## Known limitations

- GitHub and npm proxy README images, so pixel counts are approximate and unique visitors are not counted.
- Excel: chart sizes are approximate (default column width and row height); chart formatting beyond data, colors, title and legend is not drawn; charts are listed above the table, not placed over the cells.
- DOCX comments are not threaded and are not shown in the margin.
