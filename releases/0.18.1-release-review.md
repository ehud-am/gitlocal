# GitLocal v0.18.1 Release Review

## Scope

- Release: `v0.18.1` (PATCH).
- Release date: 2026-11-08
- Items: #137 (terminal fails to start), #136 (".." row in the folder view).
- No new dependency.

## Summary of changes

- #137: `node-pty` 1.1.0's tarball has `prebuilds/darwin-*/spawn-helper` at mode 0644 (checked with `tar tvzf`), so `posix_spawn` of every macOS shell fails and the session manager answers "Failed to start a terminal session on this platform." `src/terminal/spawn-helper.ts` (`ensureSpawnHelperExecutable`) adds the execute bit to the build and prebuild helpers; `spawnRealPty` runs it once before the first spawn. `scripts/verify-node-pty.mjs` (postinstall) does the same before its spawn check, so a working prebuild is no longer rebuilt from source. No terminal code changed between 0.17.0 and 0.18.0, so the trigger on the reporting machine is most likely an install where the postinstall rebuild did not run or failed [likely; the reporter's server log was not available].
- #136: `ContentPanel` takes `onOpenParent`; the folder table shows a ".." row first (click or double-click), also in an empty folder. `App.tsx` passes `handleNavigateParent` (same as the toolbar button: subfolder -> containing folder, root -> parent folder with the leave-repository dialog), and leaves it out when `/api/repo/location` reports `atFilesystemRoot`.

## Verification

- Server tests: 524 pass as a non-root user (as root, the same 13 permission-based tests fail as before).
- UI tests with coverage: 1047 pass, per-file thresholds met.
- `npm run lint`, `cd ui && npx tsc --noEmit`, `npm run build`: clean.
- Built server on Linux: terminal sessions start at the root, a subfolder and a file's folder.

## Known limitations

- The macOS spawn failure itself could not be reproduced in the Linux build environment; the fix was checked with unit tests on file modes.
- A read-only install location (for example a root-owned global prefix) can't be repaired at runtime; the error is logged and the postinstall repair still applies.
