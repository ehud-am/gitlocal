## Adjudication Log

- `FileTree.tsx:64-102` (`toggleDir` `useCallback` deps on `nodeStates`, disputed by Pass 2): **kept, with corrected guidance**. Adjudicator confirmed `toggleDir` reads `nodeStates` synchronously (not via a functional setState updater), so Pass 1's suggested fix (remove `nodeStates` from deps) would reintroduce a stale-closure bug; the underlying closure-churn observation is accurate. Correct remedy is a ref-based read or fully functional updates, not a bare dependency removal. See FT-001.

## Architecture Notes

`FileTree.tsx`/`FileTreeNode.tsx` form a clean container/presentational split: `FileTree` owns async state (a `Map` keyed by path, three effects for manual toggle/branch-refresh/selection-driven auto-expand) and recursive rendering; `FileTreeNode` is a pure, stateless row renderer. This is the correct structure and is the "real" widget that `PickerPage.tsx` (Batch D, PK-009) copies markup from without behavior — confirmed: `aria-expanded` here genuinely reflects live state (unlike `PickerPage`'s hardcoded `false`, FT-011) and the chevron rotates from real `isExpanded` (vs. FT-012's static copy). However, neither file implements keyboard navigation at all — no `onKeyDown`, no `tabIndex`, no roving focus — despite using the ARIA tree/treeitem roles, which per the ARIA APG require full keyboard operability (FT-010). So the Batch D contrast needs a caveat: `FileTree` is more correct than `PickerPage` (real expand state, real data-driven ARIA) but is not a fully keyboard-accessible tree widget either. The `Map`-of-`NodeState` plus three overlapping `useEffect`s design is functionally reasonable but fragile: two of the three effects declare `nodeStates` in their dependency array while also calling `setNodeStates` inside, causing redundant re-invocations on unrelated state changes (FT-001, FT-002); the third effect does not have this problem despite Pass 1 claiming it does (FT-003). A future refactor could consolidate expansion-state management into a single effect or reducer to make the dependency graph easier to reason about.
