## Adjudication Log

- **RC-007**: rejected at Phase 5 (dead-code) fix time — re-verified via grep and found `pluralize()` in `BranchSwitchDialog.tsx` is already file-private (never had an `export` keyword), so there is no `export` to strip and no dead code to remove; the function is a legitimate single-use internal helper, exactly as the finding's own evidence describes ("not dead in the strict sense"). No Phase 5 action applicable. The finding's actual actionable angle — consolidating this single-use helper with `RepoContextHeader.tsx`'s duplicated inline pluralization ternaries — is a duplicate-code concern tracked under RC-006 (Phase 6 scope), not dead-code removal.
- **RC-001 fixed (Checkpoint D4)**: extracted a `CloseIcon()` component in `RepoContextHeader.tsx`, following the same pattern as the existing `ChevronIcon`/`EditIcon`/`HomeIcon`/`ReadmeIcon` named icon components, and used it at both changed-files-panel close-button sites, removing the duplicated inline SVG.
- **RC-002 fixed (Checkpoint D4)**: collapsed the `items.length > 0` and empty-state changed-files-panel branches into a single `changedFiles ? (...) : null` section with a conditional header-actions block and conditional body (list vs. "No changed files to review." message), removing the duplicated section/header/close-button wrapper. Verified against `RepoContextHeader.test.tsx`, which asserts only on accessible role/text content, not exact DOM structure, confirming the collapse doesn't change observable behavior.
- **RC-003 fixed (Checkpoint D4)**: extracted a parameterized `ResponsiveNavButton({ icon, label, onClick, disabled })` component rendering the icon-only (small-screen) and labeled (large-screen) `Button` pair, replacing ~55 lines of duplicated Home/Readme button JSX with two one-line usages.
- **RC-006 fixed (Checkpoint D4)**: moved `pluralize(count, singular, plural?)` from `BranchSwitchDialog.tsx` (file-private) to the shared `ui/src/lib/utils.ts`, imported it in both files, and replaced both inline singular/plural ternaries in `RepoContextHeader.tsx` (local-changes badge, changed-files-panel path count) with calls to the shared helper. Output strings confirmed byte-identical to the prior inline ternaries.

## Architecture Notes

This unit is a presentational pair: `RepoContextHeader` is a fairly large (400+ line) single-file component mixing four loosely-related concerns — branch selector, sync/remote status badges, a changed-files panel, and an expandable details drawer — plus five inline SVG icon components. It composes cleanly with `BranchSwitchDialog` (passed through as a `branchSwitchDialog` ReactNode prop rather than imported directly, keeping `RepoContextHeader` decoupled from branch-switch business logic). The main structural smell is repeated JSX shapes (icon-only/labeled button pairs, the two changed-files-panel branches, inline pluralization) that would benefit from small local sub-components or a `pluralize` utility shared between the two files (RC-001, RC-002, RC-003, RC-006/RC-007). The confirmed unused `syncActionLabel` prop (RC-008) suggests either an incomplete feature or drift from a prior refactor — worth flagging in the architecture review as a signal to audit for other props threaded through App.tsx that aren't actually consumed downstream.
