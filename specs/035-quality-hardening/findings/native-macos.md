## Adjudication Log

- `GitLocalService.swift:96-104` (silent regex-compile failure framed as an unbounded hang, disputed by Pass 2): **kept, downgraded**. Adjudicator confirmed the independent 10s startup timer always bounds completion regardless of the regex outcome — real issue is fragile silent-failure style, severity low not medium. See NM-003.
- `ViewerWindowController.swift:51-97` (11 one-line `@objc` wrappers, disputed by Pass 2 on severity): **kept**. Adjudicator confirmed all 11 are genuine `#selector` targets for AppKit menu wiring, not gratuitous duplication — low severity confirmed. See NM-006.
- `AppDelegate.swift:74-238` (menu-building boilerplate, disputed by Pass 2 on severity): **kept**. Adjudicator confirmed this is standard verbose AppKit idiom with no correctness risk — low severity confirmed. See NM-009.
- `main.swift:1-9` (claimed missing error handling for `AppDelegate`/`NSApplication` init, disputed by Pass 2): **rejected**. Adjudicator verified `NSApplication.shared`/`AppDelegate()`/`setActivationPolicy`/`activate`/`run` are all non-throwing, non-failable APIs — there is nothing here that can fail. Pass 1's evidence describes error-handling concerns that don't apply to this file's actual content. Dropped, not carried forward.
- `AppDelegate.swift:1-298` (no single-instance guard, disputed by Pass 2 as an in-scope-vs-accepted-tradeoff question): **kept**. Adjudicator confirmed via grep that no single-instance mechanism exists anywhere in the codebase — the technical premise is accurate, kept at low severity as a plausible accepted tradeoff rather than a hard bug. See NM-014.
- **NM-006 + NM-009 deferred (Phase 6 disposition)**: both findings' own evidence already concludes these are idiomatic, necessary AppKit patterns (distinct `@objc` selector targets for menu wiring; verbose but standard `NSMenuItem` construction) rather than problematic duplication — consolidating either would require a larger design change (e.g. a tag-based command dispatch scheme or a menu-item builder) for no correctness or maintainability benefit. Combined with this unit's explicit scope note ("review-only, excluded from LOC target"), Phase 6's consolidation pass does not act on them. Left as `deferred` rather than `rejected` since the underlying duplication observation is technically accurate, just not worth pursuing.

- **NM-010 + NM-012 + NM-013 fixed (Phase 8 Checkpoint F2)**: all three are comment-only clarifications with zero logic change. NM-010: documented why `applicationDidFinishLaunching` uses only `pendingOpenFilePaths.last` (vs. `application(_:open:)`'s full flush) at the call site in `AppDelegate.swift`. NM-012: extracted the hardcoded `"gitlocal"`/`"dist/cli.js"`/`"runtime/node"` literals in `BundlePaths.swift` into a named `BundleLayout` enum with a comment tying them to the `packaging/macos/` build contract. NM-013: added a doc comment to `AppErrorPresenter.show` in `AppErrorPresenter.swift` noting it does not terminate the app and callers must do so themselves. No test/build harness exists for this Swift-only, review-excluded unit in this environment (no Xcode/swift toolchain available); changes were verified by manual review only, consistent with how this unit's earlier Phase 4 fixes (NM-001/NM-002/NM-004/NM-011) were verified.

## Architecture Notes

This unit is a thin, well-scoped native shell: six small files (~630 LOC total) with clean single-responsibility separation — `GitLocalService` (process lifecycle), `BundlePaths` (path resolution), `ViewerWindowController` (WebKit host + JS bridge), `AppDelegate` (app/menu wiring), `AppErrorPresenter` (fatal-error UI), `main.swift` (bootstrap). No god-object; each type does one thing, and the design correctly delegates all product logic (git operations, file browsing, default-reader preference persistence) to the shared TypeScript server via HTTP/the WebKit-loaded UI, implementing only what genuinely requires native APIs (process spawning, WKWebView hosting, NSMenu, Launch Services registration). Real robustness gaps concentrate in two places: `GitLocalService`'s process lifecycle (racy completion/timeout interaction — NM-001, no SIGKILL escalation and non-blocking shutdown — NM-002, silent hang-trap on regex-compile failure — NM-003) and `ViewerWindowController`'s JS bridge (incomplete string escaping enabling script injection from filenames — NM-004, no `evaluateJavaScript` error handling — NM-005). `AppDelegate`'s menu-construction code is the one area of local, mechanical duplication (NM-009) — verbose but low-risk write-once UI wiring. The IPC between the Node child process and the Swift host is entirely a stdout regex-scrape of `gitlocal listening on <url>` with no structured protocol, no PID/port file, and no liveness/health-check beyond the initial handshake — fragile but consistent with the CLI's existing stdout-based contract (`src/cli.ts`), so this is an inherited weak coupling point worth hardening on both sides together if revisited, not unique over-engineering in the native layer. The two high-severity findings (NM-001 race condition, NM-004 JS injection) are the most actionable items for a future fix phase, notwithstanding this batch being review-only and excluded from the LOC-reduction target.
