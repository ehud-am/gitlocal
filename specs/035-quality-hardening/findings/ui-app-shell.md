## Adjudication Log

- AS-004 + AS-005 (Phase 6 Checkpoint D2): **fixed together**. Though logged under different categories (AS-004 as `efficiency`, AS-005 as `duplicate`), both describe the same underlying duplication — the 10-key query-invalidation list repeated across `refreshCurrentView`, `invalidateWorkspaceQueries`, `finalizeBranchSwitch`, and `submitFolderDelete`. Fixed as one implementation: a module-scope `WORKSPACE_QUERY_KEYS` array and an `invalidateQueryKeys(queryClient, keys)` helper in `App.tsx`, with each of the four call sites passing the appropriate full-or-subset key list. Treated as in-scope for this Phase 6 checkpoint rather than split across categories, consistent with the RC-006/RC-007 precedent of fixing cross-category findings with a shared root cause together.
- **AS-002 fixed (Phase 8 Checkpoint F1)**: collapsed the no-op ternary to `setSelectedPathType(syncStatus.currentPathType)`. Confirmed identical behavior via `tsc --noEmit` and the full `vitest run` (444/444).
- **AS-006/AS-007/AS-008 fixed (Phase 8 Checkpoint F3)**: AS-006 split the viewer-state-persistence effect into a `useMemo`'d `viewerStateSnapshot` (the 16 real data dependencies) plus a 2-dependency `useEffect` that only gates on `startupOpenTargetFetched` before persisting the snapshot — no behavior change, same write on the same triggers. AS-007 extracted a module-scope `computeEmptyState(...)` helper returning `{ title, detail, actions } | undefined`, replacing the three mutable `let` bindings. AS-008 moved the three remaining local icon components (`RefreshIcon`, `TerminalIcon`, `ViewOptionsIcon`) into `ui/src/components/ui/icons.tsx`, alongside `ParentFolderIcon`/`ThemeIcon`/`PanelToggleIcon` which an earlier checkpoint had already relocated there. Verified via `tsc --noEmit`, the full `vitest run`, and `npm run build` (bundle size unchanged within a no-op delta).

## Architecture Notes

App.tsx is the single top-level shell rendered by `main.tsx` (verified: no other file imports App), and its size is justified by genuinely cohesive app-shell responsibility — it owns query orchestration (9 `useQuery` hooks + a derived `info` memo), native-app bridge event wiring, viewer-state persistence, and several modal workflows (branch switch, git identity, folder delete). Prop drilling is shallow: state is consumed either locally in JSX or passed one level down to well-scoped child components via 2-10 named props each, not threaded through multiple layers. The main structural improvement opportunity is not decomposition into sub-components but extracting repeated logic into shared helpers/hooks: the query-invalidation key list is duplicated across four call sites (AS-004/AS-005), and `handleSelectFile`/`handleSelectFolder` are near-identical (AS-001). A `useViewerNavigation`-style hook or a shared `QUERY_KEYS_TO_INVALIDATE` constant would reduce maintenance risk without fragmenting the shell's cohesive orchestration role. **This verdict (AS-003) satisfies tasks.md T018 and closes the plan.md Q1 "god component" question for App.tsx.**
