## Adjudication Log

- `button.tsx:14` (`outline` button variant unused outside tests, disputed by Pass 2): **kept** — meaning the Pass 2 adjudicator upheld the Pass-1 finding as legitimate dead code (as opposed to rejecting/downgrading it), not that the code itself should stay unchanged. Adjudicator confirmed via repo-wide grep that no non-test call site exists, and that every sibling variant in the same `buttonVariants` map except `outline` is actually consumed by app code — a legitimate, low-severity dead-code finding rather than intentional design-system surface. See PM-004. Phase 5 fix: removed the `outline` variant from `buttonVariants` and repointed the `asChild` test case (`button.test.tsx:20`, previously the only exerciser of `outline`) at `variant="secondary"` so it continues covering `asChild` rendering behavior.
- PM-002: fixed by deleting the empty `InputProps` interface entirely (rather than just un-exporting it) and inlining `React.InputHTMLAttributes<HTMLInputElement>` directly into the `forwardRef` type parameter, since the interface added no typing value beyond its base type.
- **PM-003 fixed (Phase 7 Checkpoint G1)**: simplified `updateBranchCacheAfterSwitch`'s filter predicate in `app-helpers.ts` from `!(option.name === nextBranch || (option.scope === 'remote' && (option.trackingRef === target || option.name === nextBranch)))` to `!(option.name === nextBranch || (option.scope === 'remote' && option.trackingRef === target))`, removing the redundant inner `option.name === nextBranch` disjunct per the finding's algebraic reduction. No behavior change. Verified via `tsc --noEmit` and the full `vitest run` (`App.helpers.test.ts` covers this function).

## Architecture Notes

This unit is a clean, conventional shadcn/radix-style primitives layer plus two small presentation-mapping modules (`app-helpers.ts`, `sync.ts`). The Radix wrapper components (dialog, dropdown-menu, switch, button, input) are boilerplate-consistent, fully consumed, and free of real bugs. `app-helpers.ts` and `sync.ts` are appropriately scoped pure-function modules with good test coverage (`App.helpers.test.ts`) and no unused exports beyond PM-001/PM-002. The one real gap is architectural rather than local to this unit: `ui/src/lib/utils.ts` currently holds only the single `cn()` classname helper, even though it is the most natural shared home for the triplicated path-utility functions (`parentPathOf`/`basenameOf`) that Batch C's CP-009 found duplicated across `App.tsx`, `ContentPanel.tsx`, and `markdown-navigation.ts` (plus a near-duplicate `basenameOfPath` in `markdown-output.ts`). Those call sites live outside this unit's file list so the duplication itself isn't re-flagged here, but the architecture review should record `utils.ts` as the intended consolidation point — it's currently under-utilized as a shared-lib module despite the project's existing convention of putting cross-cutting non-React helpers in `ui/src/lib/`. No near-duplication was found between `app-helpers.ts`/`sync.ts` and `App.tsx` logic itself, and PK-001's duplicated icon components (Batch D) live outside this unit's files, so no new evidence either way on a shared icons module was gathered here.
