## Adjudication Log

- CP-009 (Phase 6 Checkpoint D2): **fixed**. Consolidated the triplicated `parentPathOf`/`basenameOf(Path)` into `ui/src/lib/utils.ts` (the project's existing convention for cross-cutting non-React helpers) rather than a new `path.ts`, since `utils.ts` already existed as the designated consolidation point. `ContentPanel.tsx`, `markdown-navigation.ts`, `markdown-output.ts`, and `App.tsx` now all import the shared implementations; call sites unchanged.
- `content-panel-selection.ts:19,35` (`selectNativeControl`/`selectElementContents`, dead-code, disputed by Pass 2): **rejected**. Adjudicator confirmed both are called internally within the same file (`selectElementContents` recursively and via `selectContentPanelScope`; `selectNativeControl` via `selectContentPanelScope`), and `selectContentPanelScope` is actively used by ContentPanel.tsx's select-all keyboard shortcut. Not dead code — only an unnecessary `export` per knip, below the threshold for a logged finding.
- `CodeViewer.tsx:22-39` (hljs `registerLanguage` calls, efficiency, disputed by Pass 2): **rejected**. Adjudicator confirmed CodeViewer is lazy-loaded (`ContentPanel.tsx:28`), so the 17 `registerLanguage` calls run once per chunk-load, not per-render. Marginal, already mitigated by existing code-splitting — not an actionable finding.

## Architecture Notes

ContentPanel is the largest content-rendering unit in the app but is architecturally sound (see CP-010's verdict): its size is justified by one cohesive responsibility, and it already delegates content-type rendering, editing, deletion, creation, and markdown export to sibling components. A recurring, unit-spanning smell is small path-utility duplication — `parentPathOf` is implemented identically in three places (App.tsx, ContentPanel.tsx, and a more-robust variant in markdown-navigation.ts) and `basenameOf`/`basenameOfPath` twice; consolidating into a shared `ui/src/lib/path.ts` would remove this triplication app-wide (CP-009). Several files in this unit (json-tree.ts, markdown-frontmatter.ts, markdown-output.ts, markdown-navigation.ts) export types/functions used only internally — these are knip-flagged "unused exports," not true dead code, and are logged as low-severity export-hygiene items rather than treated as unreachable code (CP-005 through CP-008). Two effect hooks (InlineFileEditor.tsx, MarkdownShareActions.tsx) omit dependency arrays for their native-command listeners, inconsistent with App.tsx's equivalent, correctly-dependency-arrayed listener (CP-001/CP-002).
